# ADR-0013：获批赛事的整套办赛材料

状态：已实施，CAAU-033；用户确认获批后、整套提交统一审核。

## 决策

复用已有承办申请的版本化文档执行引擎（草稿CAS、提交幂等、审核动作、私有附件、版本差异和审计），以新增的可空唯一`materialEventId`明确区分两种文档。空值仍为原承办申请；非空值为对应已获批赛事的办赛材料。新增事件材料创建/列表接口，详情、附件和命令共用原执行接口，减少另建一套状态机与权限行为的风险。物理表名保留兼容，不将办赛材料算入承办申请列表。

- `POST /event-materials`只接受eventId/key，通过已获批承办申请解析机构并校验当前经办授权；一赛事一套材料，重复进入返回既有文档。
- `GET /event-materials`与原申请列表互斥过滤。列表显式白名单返回摘要，不返回草稿、银行账户或手机号；详情和文件按既有机构/总部审核授权读取。
- 执行状态复用DRAFT、PENDING_REVIEW、IN_REVIEW、NEEDS_SUPPLEMENT、APPROVED，材料不支持终止驳回（仅退回补充）。材料通过分支只记录结论，不创建Event、EventOrigin或承办关系。
- `materialEventId`追加外键、唯一约束与不可变检查，材料文档禁止拥有approvedEventId及REJECTED状态；保留原申请获批必须创建赛事的不变量。只追加第10个迁移，不修改旧迁移。
- 附件沿用营业执照/场地照片两个既有私有分类和确认/版本绑定；其他附件仍选交。银行、报名时间、手机号追加到文档草稿与不可变提交快照，仅在材料模式接受并在提交时强制完整；旧申请表单不新增必填项。
- Web `/materials`默认显示整套材料审核；旧单份流程位于`/materials/legacy`，旧task/material深链继续兼容，不改写历史。
- 小程序新增`pages/event-materials/index`，由“我要办赛→办赛材料”进入；共用已有页面协调逻辑并以显式materials模式选择接口/字段，保留冲突和未确认命令重试保护。

## 验证范围

隔离数据库验证：七项缺失、非法日期/手机号、获批前拒绝、重复建档、并发版本冲突、跨机构访问/文件、整套V1退回→V2通过、幂等重放、不可变历史及赛事数量不变。原申请和旧材料测试全部继续运行。Web实际审核详情与微信页面另行检查；不将本地测试会话当正式微信登录或真机验收。

实际结果见[任务记录](../planning/roadmap.md)：隔离数据库50/50及Web E2E 9/9通过，微信真机另行验收。
