# ADR-0028：智能助手三级记忆

状态：2026-09-25 本地实现，环境验收见 roadmap。

## 决策

智能助手的记忆分为三个独立来源，均由当前登录身份访问：

1. **L1 会话**：`AgentTurn` 是原始记录，`AgentSession.contextSummary` 与 `summarizedThroughSequence` 是可重建的压缩上下文。超过 30 条未压缩消息时，只把较早的消息交给模型生成客观摘要，至少最近 20 条保留原文节选；模型每轮最多接收 30 条未压缩消息。失败保留原记录与旧摘要，不阻断聊天。摘要只帮助理解指代，不能授权、确定业务事实或代替需求单。
2. **L2 任务**：沿用 `AgentTask`、`AgentPlanningRequest`、候选快照和 LangGraph checkpoint。任务参数、来源、revision、票据和权威赛程均不从聊天摘要推断。继续使用现有鉴权、CAS、过期、人工确认及只保存单场 DRAFT 的边界。
3. **L3 长期偏好**：`AgentMemory` 只保存账号本人明确确认的个人偏好（回答方式或一般排赛倾向）。Web 和小程序设置提供添加、查看、软删除；识别到“请记住：回答……”时只提出建议，点击“保存这条记忆”后才生效。最多 30 条、每条 300 字。偏好可跨新对话用于回答和方案讨论，不作为排赛约束、组织规则或权限。业务事实仍从授权业务接口实时读取。

## 权限与隐私

- 所有会话读取、摘要生成前后的保存、长期记忆读取与变更逐次认证。会话撤权后旧摘要不得进入模型；长期偏好按 owner 隔离。
- L1 摘要只来自已授权的本会话 turn，保存已处理到的持久序号；并发摘要更新用 `summarizedThroughSequence` 条件写入，避免旧结果覆盖新结果。
- 长期偏好正文不进入技术日志和审计 context；审计只记录当前操作者、动作和记录 ID。删除时清空正文并保留无正文墓碑行供追溯，立即从后续模型上下文排除。新对话不继承旧会话或任务，只能读取本人仍有效的长期偏好。
- 密钥、登录令牌和业务附件不属于记忆。服务端阻止明显凭据字符串；不能把该检查当作完整的敏感信息识别。用户应避免把私密资料加入偏好。

## 边界与后续

本阶段不用向量数据库，也不将聊天自动写成长期知识。知识检索需要来源、版本、访问范围和删除/撤权同步机制，作为独立任务实施。会话摘要可能遗漏细节，用户应以原对话、结构化需求单与当前业务数据核对重要条件。摘要生成是额外模型调用，纳入现有调用级用量账本；连接/额度失败时旧消息仍保存。
