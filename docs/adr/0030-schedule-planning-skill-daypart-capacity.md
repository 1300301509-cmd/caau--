# ADR-0030：赛程编排 Skill 与每日分时段场数约束

状态：本地实现，CAAU-087；2026-09-27。

## 背景

用户在已有整套排程需求后补充“每两只队伍各交手一次，上午最多排一场，下午可以排两场，晚上可以排一场”。旧流程在生产 Qwen 路由后仍用原话正则检查是否单循环，并且需求/候选结构没有分时段场数，导致清楚的补充没有进入需求单。

## 决策

- 产品运行时新增可版本化 `SCHEDULE_PLANNING` Skill，负责给模型提供排程需求提取方法。已有 `INTENT_ROUTING` 与 `TOOL_SELECTION` 继续各管路由和工具建议。Skill 是未受信的指令，不登记工具、不增加权限。
- 生产 Qwen 的排程语义采用结构化提案；后端不再要求单循环必须命中某条原文关键词。服务器仍检验提案 schema、当前赛事/参赛记录、条件范围与来源，并将需求留在人工确认状态。模拟适配器的固定表达仅供自动化回归。
- `DAYPART_CAPACITY` 按上午、下午、晚上保存每日最大场数、北京时间具体起止时刻和 `EVENT`（整个赛事）/`VENUE`（每场地）统计范围。缺失时刻或口径只记录待补，不能确认。已有需求按 daypart 合并后续补充，revision、原话来源及确认失效规则沿用需求单。
- 候选搜索按场数上限剪枝，结果再独立计数核验；三个时段齐备时仅在这些时段排比赛。前端在人工确认前显示这条计算含义。任何条件不被支持或结果独立校验不通过，都不得声称找到合规候选。
- 模型调用输出仅作为提案。只读、需求收集、候选和单场 DRAFT 的固定工具目录与逐次业务鉴权继续生效；整套候选没有保存/发布工具。

## 后果与限制

需求条件保存在现有 JSON 列，本次不增加数据库迁移。新 DTO 由 Nest 生成客户端，两端展示相同条件。真实模型仍可能返回无效结构；该轮明确失败并保留用户输入，不写半张需求单。自然语言覆盖率需要独立样例集和真实模型多轮验收，单次成功不代表长期稳定。正式整套赛程保存/发布和微信运行时另立任务。
