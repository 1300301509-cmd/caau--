# ADR-0015：球队主档案与赛事球队资料分离

状态：CAAU-041 实施。

## 决策

`Team` 保存球队主档案与录入机构，`EventTeam` 保存赛事独立快照；`eventId + teamId` 唯一。赛事列表读取自身 `profile`，不联表取主档案资料。`sourceTeamRevision` 只表示初次复制来源，不构成同步订阅。

`TeamMembership` 将 InternalUser 与 Team 关联，不引入新的登录身份、不复用承办方角色。当前运行账号仅有该表 SELECT 权限，后续认领流程经过单独审查后追加写入能力与绑定历史。

`TeamVersion`、`EventTeamVersion` 保存每次资料/状态修改及操作者。数据库触发器禁止版本表更新、删除和清空；运行账号不拥有实体删除权限。实体 ID、归属、创建信息及赛事来源版本不可改变。修改须 revision 严格递增，服务层 CAS 与 Serializable 事务处理并发，版本与审计同事务提交。

新增独立 `teams` 模块，复用 AuthorizationService.run 和既有用户/组织/赛事授权模型；Prisma 仅经 @caau/database 使用。DTO 与控制器生成契约，两端不得引入服务端实体。创建球队并加入赛事由该模块在同一事务中完成，不修改赛事本身。

## 结果与限制

比赛记录不会随球队改名、联系方式调整、归档或未来认领而改变。不同比赛可以保存不同负责人和联系方式。相同球队可以参加多场比赛，但重复加入同场比赛不会创建第二条或刷新旧资料。

资料搜索及分页当前在前端对授权结果进行；规模扩大时应改为服务端分页/检索。账号邀请认领、角色细分、球队合并、球员名单、队徽上传和比赛报名审批不包含在本阶段。验证与实际交付状态见 [开发计划](../planning/roadmap.md)，业务边界见 [球队管理](../product/team-management.md)。
