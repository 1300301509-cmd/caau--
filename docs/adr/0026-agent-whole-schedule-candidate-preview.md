# ADR 0026：已确认需求的整套候选赛程（CAAU-064）

状态：本地实现；场次进度、发布规则及正式赛制需业务确认。参见 [CAAU-063 需求版本](0025-agent-planning-requirement-revisions.md)、[赛程算法](0016-event-scheduling-engine.md)、[候选预览规格](../product/agent-schedule-candidates.md)。

## 决策

- **独立预览**：只接受 owner 有权、已确认且未失效的 `AgentPlanningRequest` 当前 revision；另需基础赛程 revision、明确赛制、完整配置及配置来源、显式固定场次 ID 数组。当前仅支持单循环，不转换淘汰赛或自行设置时间/场地/时长/缓冲/休息。明确标记配置来自现有赛程还是此次完整输入；日期必须与需求的 MUST 日期范围一致，参赛列表必须等于当前有效 `EventTeam`。已有已发布/淘汰赛基线拒绝重新编排；起始时间已过或本版本已安排工作人员的场次必须固定。当前缺少独立场次已开始/完成状态，不能臆测；对已发布版本从严拒绝，场次进度字段和额外固定规则待后续业务模型确认。
- **纯计算、独立校验**：复用 scheduling 的单循环对阵生成和北京时间场地时隙，而不调用会写 `EventSchedule` 的 `SchedulingService.generate()`。有界回溯分配场次，先检查时隙容量和每对球队硬条件允许的时隙；不会放宽 MUST。`auditCandidate` 与搜索独立重新检查对阵数量/重复、全部场次时间、场地重叠及缓冲、球队同时比赛和最短休息、硬条件与固定场次。检验未通过绝不返回 FOUND。
- **偏好不冒充成果**：团队 PREFER 时段在搜索时局部排序，但不宣称全局最优；逐条标 `SATISFIED`、`UNMET` 和原因。`AVAILABLE` 描述“可在”，不是唯一可用窗口；若标 MUST 却未说明“只能在”，不能构成可校验的安排硬约束，候选计算先拒绝并要求修订为 ONLY/BLOCK 或软偏好；ONLY/BLOCK 才约束或优化安排。单循环每两队本来就交手一次，未指定日期/轮次的 MATCHUP 条件不能当优化成果，必须修订/澄清后再计算，不能擅改场次总数。未来引入“提前交手”须先确认可检验的时间/轮次语义。技术限额（最多 3000 时隙、66 场、12000 节点及 1.5 秒）不是业务赛制限制。
- **三个结果**：`FOUND` 经独立校验；`PROVEN_CONFLICT` 仅在容量不足、某对阵不存在硬条件允许的时隙或已有固定场次本身违反约束等**必要条件**明确冲突时返回；其它回溯失败、顺序受限、预算/时间耗尽统一 `SEARCH_LIMIT`（未找到≠证明无解）。不支持的赛制/条件在计算前 400/409，不能忽略后声称满足。
- **恢复和权限**：不可变 `AgentScheduleCandidate` 前向新表存需求版本、基线快照（含赛事配置、旧场次及本版本工作人员安排标志）、参赛修订快照、显式固定范围、候选/检查/偏好报告。无外键指向正式版本/命令票据，无赛程保存或发布端点；恢复/按 ID 读取/Studio 校验前重新核验 owner、赛事操作/赛程读取权限并比较当前快照，需求修改、基线/工作人员或参赛修订后动态标 `STALE`，不返回可执行授权。恢复若无候选返回 404。

## 明确限制及后续

约束搜索的顺序和时间上限可能错过可行方案，不能把 `SEARCH_LIMIT` 描述为无解。单循环主客方向沿用算法，不代表正式主客场/轮次业务规则。正式开始/完赛状态、外部场地不可用、跨赛事共享场地、对阵轮次偏好及自动择优需业务规则和结构化数据后单独评审。本次操作只做建议，不覆盖、生成或发布正式赛程。模拟/隔离真实数据库、真实千问、Studio HTTP 图、官方 Studio 页面、微信及远程逐层报告，互不替代。
