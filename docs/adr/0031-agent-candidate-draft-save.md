# ADR-0031：整套候选赛程受控保存草稿

状态：本地实现，CAAU-088；2026-09-27。

## 背景

CAAU-064/087 已有独立候选快照和硬条件校验，但候选只是预览。用户需要人工核对后保存成可继续处理的赛程草稿；自然语言和模型输出不能直接成为写库命令。

## 决策

- 固定工具目录增加 `schedule.draft.generate`，与 `schedule.draft.adjust` 和 `schedule.publish` 分离。Skill 只建议何时使用能力，不能调用数据库或绕过按钮。
- 新确认票据绑定候选 ID、owner、赛事、需求版本、基础赛程版本、候选内容哈希、工具版本、固定 commandId 与 30 分钟期限。准备票据不修改赛程。确认请求只带候选 ID 与哈希，不能提交替换后的配置或比赛列表。
- 确认和取消均重新鉴权。确认在 Serializable 事务内锁定票据，重验候选状态与硬条件，并以赛程 revision CAS 写一个 DRAFT 版本；回执和票据消费同事务提交。已执行票据在重新鉴权后回放原回执。
- Web 与小程序都展示候选逐场明细、确认和取消按钮、原执行版本和当前赛程版本。刷新从服务器恢复票据与回执。模型对话中的“好的”不触发写入。
- 沿用候选阶段的保守规则：已发布和淘汰赛基线拒绝；过去时间及有人员安排的场次必须明确固定。系统尚无独立开赛/完赛状态，不推断现场比赛进度。

## 后果与限制

新增前向迁移保存不可变绑定和回执。候选预览仍可独立使用；只有显式确认才产生正式版本。当前只保存草稿，不提供 Agent 发布、批量审批或对已发布赛程的智能改写。真实模型稳定性、微信运行时和远程环境按独立证据验收。
