# ADR 0024：统一助手只读赛程工具与查询来源

状态：已实施（CAAU-062）；沿用 [ADR 0019](0019-agent-orchestration.md)、[ADR 0022](0022-agent-dialogue-task-routing.md) 和 [ADR 0023](0023-independent-agent-studio.md)。

## 决策

- 路由 `QUERY` 与 `CHAT`、明确的单场 `START/CONTINUE` 分开。模型仅提出 `schedule.list` 或 `schedule.match` 的结构化查询计划；封闭注册表声明名称、用途、Zod 参数、`schedule.read` 权限与 `mutates: false`。服务端在当前身份与事务中解析赛事、北京时间日期与指代，调用 scheduling 公共只读用例；不允许模型执行 SQL、写操作、确认票据或发布。
- 回答由授权赛程快照确定性生成：赛事名、查询日期、草稿／已发布状态、版本及逐场对阵／时间／场地。未安排、无赛程、无匹配、无球队与未授权不是“有空”；歧义先澄清，不猜测赛事或场次。至多列出前五场并标注总数与缩小范围建议；多场详情提供选择。显式日期优先，周一到周日及跨年周由服务端按北京时间计算。查询仅读当前赛程，不改变活动调整任务。
- 有实际赛程读结果（包括零结果及歧义场次）时，同一事务写入原用户／助手 turn，并在助手 turn 的 `structured` 中保存 `{ kind: 'QUERY', source: { eventId, revision, status, matchId?, matchIds? } }`。不需要新的业务表或已执行迁移改写。会话读取、列表、模型历史和 Studio 恢复**先遍历全部查询结果**并逐个核验当前用户对来源赛事的 `schedule.read`，不能只核验最近 20 条或活动任务。资源继承赛事的读取策略；历史回答含旧版本号，不冒充当前赛程。新的查询每次重新读快照，写入回执前重验权限与版本／状态。删除赛事权限后，即使从未创建调整任务，也不得恢复历史或送给模型；跨赛事任意来源被撤权则整会话不可恢复。
- `lastQuery` 仅从已鉴权持久来源读取，只有唯一单场才有 `matchId`；“刚才那场”没有可确认来源时要求澄清。用户**明确发起单场调整**才能将该引用转为新的单场任务候选，仍走原纯预览、人工绑定票据、CAS 与事务回执；任何查询或普通问题均不能确认/写赛程。页面提示不覆盖活动任务赛事，明确提到的已授权赛事名需单独解析。Web、小程序消费同一生成客户端，Studio 使用相同模型、业务节点并展示 `plan_query → execute_query → save_query` 分支。

## 取舍与边界

查询历史授权扫描与会话 turn 数成正比；未来若会话长期增长，应引入前向迁移的索引／来源关系表，**不能**以仅检查最近历史或匿名脱敏代替鉴权。多场来源只保存实际显示的比赛 ID；版本变更后旧历史仍以历史版本标注，下一次查询重新读取。模拟、隔离数据库与 Web 浏览器、真实千问、微信开发者工具／真机、远程生产需分别验收。
