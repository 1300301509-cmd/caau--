# ADR-0004：CAAU-005 全段技术设计

状态：技术方案采用；第一段实现赛事/任务创建、指派、要求维护、发布、查询及总部 Web；本文保留全段原计划，第二段本地已实现范围及与生产目标的差异以 [ADR-0005](0005-material-execution.md) 为准；云存储/扫描/自动回收等仍是计划。依据 [确认规格](../product/mvp-material-review-spec.md)、[权限底座](../runbooks/authorization.md)。不覆盖 ADR-0003 或历史迁移。

## 1. 模型与权限锚点

- `Event.id` 同时为 `EventScope.id` 外键，一对一共享 UUID；Event 保存名称、说明、创建者和时间。创建事件、锚点、创建者 EVENT_MANAGER 授权和审计同事务。旧孤立权限锚点保留，不自动变成正式赛事。
- `MaterialTask.id` 同时为 `TaskScope.id`，`eventId` 指向真实 Event；保存任务名称、内部配置草案 JSON、revision、DRAFT/PUBLISHED、发布时间。TaskScope 仍是当前经办/审核授权的唯一来源，不在客户端复制权限状态。一个赛事可有多个任务、多个承办机构，每任务指派一家机构的一名经办人和一名审核员。
- `RequirementVersion` 是发布时的不可变快照，包含材料清单及每项稳定 UUID、名称、必交性、说明、模板版本、格式扩展名、字节上限、截止时间、合格标准；JSON 由显式 Nest DTO 与运行时递归校验约束，不接受任意字段。第一段只生成 V1，(taskId, version) 唯一，第一段还限制每任务一条发布快照。数据库触发器禁止快照修改/删除，已发布任务配置也不可修改。
- 第一段的“草案”是总部任务配置，不是承办方材料草稿。发布前只允许本赛事管理员查看/修改；发布后指定经办人和审核员才可查询真实任务及对应要求。系统管理员没有业务资料权限；列表在数据库按授权范围过滤，详情、编辑、发布再逐次鉴权。
- `AssignmentHistory` 追加记录 taskId、原/新经办与审核授权 UUID、操作者、时间；事务内更新锚点、配置 revision、历史和安全审计。历史 UUID 不用于授予当前访问权。

## 2. 第一段事务边界与兼容

授权模块导出统一事务入口及明确的锚点创建/指派服务，业务模块只通过服务参与同一个 Serializable 事务，不跨域直接改权限 repository。身份、角色、赛事权限、任务归属、指派冲突和用户/成员 active 状态在事务内重新检查；任何失败（包括审计写入失败）整体回滚。乐观 revision 与数据库串行化冲突返回 409，客户端须刷新后确认，不能静默覆盖。

总部管理员可在自己的赛事上选择系统管理员已建的有效 ORGANIZER/REVIEWER 成员，业务指派服务仅创建本赛事对应角色授权，不授予系统管理能力。候选目录只对无经办角色的总部赛事管理员开放，提供选择所需最小机构/姓名/成员 UUID，不含会话或业务资料。系统管理员仍负责账号/组织/角色维护；Web 提供必要账号与成员登记表，不要求手改数据库。

第一段支持发布前配置更新和重指派（不存在材料草稿）；发布操作检验完整配置、当前指派有效性，原子生成 V1、标记 PUBLISHED、递增 revision、记录审计。重复发布返回现有已发布任务，不产生 V2；并发请求冲突可 409 后刷新重试。发布后本段不开放要求更新或重指派，并返回明确 409。这是本段能力边界，不把“发布即永远不可调整”冒充确认业务规则；后续如实现未开始办理前更新，必须追加要求版本并处理客户端旧版引用。

已关联真实任务的旧 `/authorization/task-scopes/:id/reviewer` 写入口拒绝修改，必须走业务用例，避免绕过 revision、发布保护和指派历史。停用成员/用户保持即时生效；历史授权和业务记录不硬删除。正式赛事撤权不能由客户端删除业务记录代替。

## 3. 第二段计划：草稿、提交与审核

- `MaterialDraft` 引用 taskId、requirementVersionId、当前 assignment generation、baseSubmissionId（退回后来源），使用 revision 乐观锁。草稿内容与附件绑定可变，但必须属于当前经办机构和有效任务指派。
- `SubmissionVersion` 引用准确 requirementVersionId 和提交时 assignment generation，记录版本号、提交者、时间、不可变内容和附件引用；(taskId, version) 唯一，禁止 UPDATE/DELETE。V2 来源 V1 只复制生成新草稿，旧版本不覆盖。
- `ReviewRecord` 指向明确 submissionId，记录审核者、PASS/RETURN、原因、问题材料 UUID、修改要求及可选新截止时间；submissionId 唯一（一版一个整包结论），数据库不可变。返回要求必须引用这一版要求中真实存在的材料；审核员不能写提交内容。
- 任务状态不由通用 PATCH 暴露；命令式 saveDraft/submit/return/approve 负责状态机。审核事务同时校验当前提交指针、当前审核指派、自审冲突及唯一审核结论，写审核、更新指针/状态、创建退回草稿及审计原子提交。通过后无隐式重开。

## 4. 指派、重指派、撤权和历史（第二段准入）

发布前重指派已在第一段实现。发布后/已有草稿的换人必须锁定任务与草稿 revision、更新指派 generation 和历史、撤掉旧经办人的任务访问；不能只改 UI 菜单。旧 EventGrant 即使保留也不能越过当前 TaskScope 获取资料。跨机构移交尤其不能自动泄露旧机构材料；历史提交与审核永久保留、当前访问和历史归属分离。

用户第二段已确认并取代原未决问题：截止后可保存草稿但不得提交，总部赛事管理员延期必须留操作者/时间/原因/新旧截止；同机构交接现有草稿和材料、保留编辑记录且旧人立即失权；跨机构禁止直接转移，关闭旧任务另建新任务；提交/审核历史作者与时间不改写。具体实现决策见 [ADR-0005](0005-material-execution.md)。永久用户/机构删除不在首版能力中。

## 5. 非公开文件方案（第二段计划，非已验收）

采用服务端 `PrivateObjectStore` 接口；本地适配器用仓库忽略目录的私有文件根（无静态文件映射），部署适配器用禁 public ACL 的 S3 兼容私有桶。先实现本地适配器及契约测试；具体云账号/桶地域由部署资源确定，不提交凭据。

1. 授权申请：通过真实 task/draft/current assignment 检查，创建 `UploadIntent`（随机 object key、owner/task、材料 UUID、预期格式/大小/hash、过期时间、状态 PENDING）。key 不由前端提供，不用原始文件名拼路径。
2. 流式上传至隔离暂存对象，限制请求体、文件数及字节数；检查魔数/MIME/扩展名匹配，阻止路径穿越；恶意文件扫描通过前保持不可绑定/下载。不能仅信 Content-Type 或前端“成功”。
3. 确认：后端查对象真实 size/hash/扫描状态，重验当前授权，幂等转 CONFIRMED。超时或重复确认不得产生重复附件。失败暂存按过期清理任务回收，清理仅按数据库精确对象 key。
4. 绑定：保存草稿事务核验 CONFIRMED、同任务/同材料/当前机构和指派 generation，建立绑定；不能用其他任务 objectId 越权绑定。提交时把绑定复制到不可变版本。孤立对象回收不删任何被草稿/历史版本引用对象。
5. 下载：优先后端鉴权代理流，每次按附件所属任务、草稿/提交版本及当前权限复核。若需要短期地址，只发应用 download ticket；兑付时再次鉴权后代理内容，不给不可撤回的裸对象签名 URL。响应 private/no-store、attachment 安全文件名，令牌不放 URL；不提供公开文件链接。访问事件审计只记 UUID/字节数，不记正文。

## 6. 幂等和并发（第二段计划）

- 草稿保存带 expectedRevision，CAS 更新；0 行返回 409 和“刷新比较”，不得 last-write-wins；编辑器保存中锁按钮，失败保留本地编辑值。
- 正式提交带随机 Idempotency-Key；`SubmissionCommand` 以 actorId/taskId/key 唯一，存规范化请求 hash 和结果 submissionId。同 key 同 hash 返回已有结果，不同 hash 返回 409。事务锁任务、重验草稿 revision/附件/要求版本/截止策略，提交快照、版本号、当前指针和幂等结果及审计同事务。重试读取结果仍须当前权限。
- 并发审核用当前 submissionId CAS 和 ReviewRecord 唯一约束，一版只容许一个结论，其他返回 409；不把“重试”变成覆盖旧审核。
- 文件存储与数据库无分布式事务：用 PENDING/CONFIRMED/BOUND 状态和幂等补偿回收，不把对象上传与数据库写入假装成原子事务。

## 7. Web 与验收

沿用 React19/AntD6，使用轻量工作台、赛事列表→任务草案编辑→发布详情；明确状态文字、可见字段标签、加载/防重复点击、失败提示、发布前确认。材料逐项可配置，不预填正式数值；默认五项名称仅取确认规格。会话通过本地文件导入到内存，不放 localStorage、URL 或构建变量，标明非微信登录。选择人使用目录下拉，不要求输入数据库 UUID。窄屏堆叠表单，键盘可操作，无统计假数据。

UI 技能检索给出的极简/高对比风格可用，但营销 Hero 模式不适合内部工作台，不采纳；使用现有组件栈和系统中文字体，不下载远程字体。Context7 本轮网络查询失败，不新增依赖，按已固定版本本地类型/构建验证。

第一段真实 PostgreSQL/API 测试覆盖：发布前后列表/详情、两赛事两机构的真实业务越权、非法/停用/自审指派、草案 revision 冲突、发布快照不被改写、旧权限写入口封堵、审计失败回滚、迁移重复执行与既有数据保留。浏览器走真实 API 完成创建赛事、选择机构经办/审核、编辑要求、发布；不是 route mock 或权限探测验收。完整上传/提交/审核、小程序/微信真机及生产存储验收留第二段/CAAU-010。
