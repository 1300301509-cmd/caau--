# ADR-0022：自由对话与单场赛程任务的服务端分流

状态：已采纳（CAAU-060，本地实现；平台验收见 [roadmap](../planning/roadmap.md)）。

## 背景

CAAU-049 的消息调用默认创建 `AgentTask` 并调用赛程意图提取器，导致没有赛事时无法自然聊天；CAAU-059 统一窗口并没有改变这一服务端语义。不能依赖 Web/Taro 的前端关键词决定业务任务，也不能因支持聊天绕过旧会话撤权检查。

## 决策

- 同一 `POST /agent/sessions/:id/messages` 在服务端使用**无 checkpoint 的 LangGraph 对话路由/回答子图**；授权后的近期 `AgentTurn`、活动任务和有权预览用于本轮路由，不把聊天内容/凭据写入模型 checkpoint。`CHAT/CLARIFY/UNSUPPORTED` 只追加本会话的 USER/ASSISTANT turn、更新时间；不创建 task、确认票据或赛程版本。插入聊天不更新业务任务 revision。
- `START/CONTINUE` 才进入已有**带 PostgreSQL checkpoint** 的赛程业务图。路由模型不拥有授权或写库权；程序在模型前核验 session owner、全部历史任务的当前赛事读取权限和显式赛事，回答前再核验、保存前又核验。已有撤权会话不得供聊天复用；新建空会话不继承其历史。
- 明确不支持的跨模块、批量重排、发布等没有执行入口；模型误路由时程序兜底拒绝业务图。带活动任务的纯目标时间/相对修改有受限的继续任务规则，避免模型将“上午十点/再晚半小时”误分类为新任务。普通问题及“好的”不执行确认；单场写入仍只走 C1 绑定票据、当前 actor、CAS 与持久命令回执的事务。
- Qwen 适配器分别实现结构化路由、普通回答及原单场参数提取；无凭据时确定性适配器仅供模拟测试。通用回答没有业务查询工具，不能声称查询了未授权或未提供的数据。外部模型失败返回 503，不静默降级。两端仍只用生成的 `@caau/api-client`，消息调用独立设置 75 秒时限：路由/意图最多各 18 秒，普通回答最多 45 秒并给服务端预留时间；不自动重试模型，超时仍返回明确失败。

## CAAU-060 验收缺口修复：回答长度与消息顺序

新增前向迁移 `202609240001_agent_turn_content_order`（不改历史迁移）：`AgentTurn.content` 为 `VARCHAR(4000)`，`AgentSession.nextTurnSequence` 为逐会话计数器，`AgentTurn(sessionId,sequence)` 唯一。聊天和原业务结果节点共用事务写入器，先锁定/原子递增会话计数器两个序号，再同事务插入 USER、ASSISTANT；会话读/模型历史均按 `sequence` 排序，前端沿用接口数组顺序。Serializable 冲突只重试整个已鉴权事务；失败不留下半条问答或占用已提交序号，业务任务 CAS 不被聊天绕过。

适配器不截断供应商回复。服务端按 Unicode 码点校验完整回答最多 4000 字，超限明确返回 **502**（回答超过系统限制，不是模型连接失败），不保存问答；2000/2001/4000 字原文经接口返回和会话恢复保持一致。模型历史只取最近 10 条、每条最多 600 字的标注节选，数据库原文和两端恢复不做此截断。旧数据迁移依时间戳、同戳 USER 优先、再 UUID 确定性回填序号：历史相同时间戳的真实并发先后原本不可恢复，不能声称迁移还原了旧记录的真实顺序；新写入无需依靠时间戳或 UUID 排序。

## 运行阶段诊断与超时协调（CAAU-060 本地后续验收）

既有 12 秒供应商单次/30 秒客户端总限时导致七队赛制等真实回答在前者先行超时；最新隔离真实模型成功轮次的同类回答实际约 16–21 秒。现将结构化路由/意图设为各 18 秒、自由回答 45 秒、仅消息客户端 75 秒，所有调用 `maxRetries: 0`，不触碰确认票据超时或业务事务时限。ChatOpenAI 的结构化输出使用 `includeRaw` 只为提取可获得的 `usage_metadata`，不把原始 AIMessage 保存或记录日志。四类阶段（含显式连接测试）的单次日志仅有阶段、耗时、固定错误类型/类别、可提取的 HTTP 状态、Token 计数；错误消息、HTTP 响应、用户文本、凭据和请求头绝不序列化。无法归类的供应商异常标记 `unknown`、状态/用量为 null，不伪称已证实为限流或超时。最新证据见 [roadmap](../planning/roadmap.md)。

## 取舍与限制

该路由是最小能力，不是开放其它业务工具；普通聊天没有模型 checkpoint，恢复依赖已鉴权的数据库 turn。服务端重复发送聊天可能产生重复对话 turn，但不会创建或重复执行赛程命令；现有业务确认恰好一次依赖票据、固定 commandId 和数据库事务。供应商超时、网络重试仍会失败并要求用户核对历史；提示词降低无据编造风险，不能替代有权的数据查询。微信运行时、真机和远程环境另行验收。
