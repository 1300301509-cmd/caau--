# ADR-0029：Skill 指令与业务工具分离

状态：已采纳，CAAU-086 第一阶段；2026-09-26。

CAAU-087 增加产品运行时 `SCHEDULE_PLANNING` 键及分时段需求边界，见[ADR-0030](0030-schedule-planning-skill-daypart-capacity.md)；下文保留第一阶段的两个初始键说明。

## 背景

用户希望智能助手有多个可演进的 Skill，并能在总部「平台治理与监控」中随时修改；工具调用仍须按账号、赛事和动作授权。原路由与业务提示词写在代码中，短回复也缺少可恢复的待答问题状态。

## 决策

1. Skill 是**版本化的模型指令**。仅总部超级管理员能创建、列出、启用版本；已创建的正文不可原地修改，回滚须创建新版本。初始键为 `INTENT_ROUTING`、`TOOL_SELECTION`。没有活动版本时使用代码中的受测默认指令。服务端每轮在鉴权后读取活动版本，仅将其作为未受信的语义提示。
2. 工具是**代码登记的能力**。名称、版本、风险、权限和确认策略由静态目录及原领域服务定义，不由 Skill 文本创建或变更。模型只能提出受 schema 限制的意图/工具建议；执行点重新确认当前 actor、赛事、业务状态和参数。写入仍必须走原有绑定票据、revision CAS、事务与审计。
3. 待答问题是**业务状态**。首轮只记录排程日期/对阵歧义，关联会话、需求单、赛事、revision 和有效期。短回复只有匹配有效问题才能补条件；纯文本“确定”不能确认需求单、签发票据、保存或发布赛程。
4. 管理 API 置于 `/api/v1/observability/agent/skills`，供未来治理子模块使用；当前不开放任意代码执行、任意 SQL、工具脚本上传或管理员自定义权限规则。
5. 单场调整预览使用 `schedule.read`，因此只读账号可查看确定性预览。确认票据仅在服务端再次核验 `schedule.draft.adjust` 后签发；无此权限的预览不附可执行票据。确认时仍逐次重新鉴权。

## 后果与后续

Skill 可在线版本化且与工具实现隔离。活动 Skill 仍可能误导模型，因此结构化 schema、能力目录、当前权限与确定性校验继续是安全边界。首轮仍使用现有单类路由；复合目标拆分、依赖排序、一般化澄清及资料检索需按 [CAAU-086 计划](../planning/caau-086-agent-orchestration-plan.md)独立实现和验收。迁移、接口与实测结果见 [roadmap](../planning/roadmap.md)。
