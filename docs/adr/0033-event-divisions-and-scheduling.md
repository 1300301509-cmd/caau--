# ADR-0033：赛事竞赛组别作为排程硬约束

状态：采用（CAAU-099，2026-09-28）

## 背景

原 `EventTeam` 不带组别，赛程配置是一份赛事参赛 ID 列表，单循环会把列表中所有队伍两两配对。用户补充：每支参赛队伍有如「U12 男子组」的竞赛组别，同组才能交手。只修改模型提示词无法保证 Web、API 与智能体调用一致。

## 决策

建立赛事级 `EventDivision`，在 `EventTeam` 上绑定其 ID，并让新赛程场次保存组别归属。现存参赛记录暂可无组别以保护历史，但新生成和发布需要先归组。沿用赛事级单一 `EventSchedule` 和不可变版本；组内生成对阵，全赛事统一分配场地与时间、统一检查冲突。组别、赛事参赛记录及版本变更均使相关候选和确认失效。

权限仍由服务端当前会话、赛事与业务动作决定。模型提案与可编辑 Skill 只负责理解/澄清，不取得绕过组别校验的能力。旧发布历史不自动改写。

## 影响

球队接口、赛程 DTO 与算法、Web/小程序页面、智能体规划/候选/建队流程、OpenAPI 客户端及数据库迁移都需同步更新。组内 A/B 分池、年龄资格自动判定和跨组友谊赛另行设计。
