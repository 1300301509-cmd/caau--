# ADR-0016：确定性赛程引擎与对话入口分离

状态：CAAU-042 实施。

## 决策

后端 `scheduling` 模块提供读取、生成、逐场调整和发布能力。Web 与未来智能体均消费生成的 `@caau/api-client` 契约。算法采用确定性的轮转配对和时间槽贪心分配；相同球队顺序与约束产生相同的对阵顺序，记录 ID 和命令 ID 用于实体与幂等识别。

`EventSchedule` 保存当前工作方案，配置、场次和冲突均为结构化 JSON；`EventScheduleVersion` 在每次生成、调整和发布时保存不可变快照。JSON 用于让后续赛制扩展保持聚合原子性，DTO 仍提供明确字段，不向前端暴露任意数据库对象。当前行通过 revision 严格递增，历史表禁止更新、删除和清空。

赛程引用赛事球队 ID，并在场次中冻结显示名称。主球队档案与赛事球队隔离规则继续成立。读取当前方案时重新校验赛事球队有效状态，避免球队退出后仍把旧的零冲突结果当作可重新发布方案。

生成和调整允许产生带冲突的待发布方案，方便人工解决；发布在同一授权事务中重新校验，任何冲突返回 409。已发布方案再次操作会变为新待发布版本，旧发布版本不修改。

## 影响

未来智能体只负责收集条件、解释结果和调用命令，不能另建一套排程逻辑。自然语言不进入审计上下文或业务表；落库的是经过 DTO 校验的结构化命令。复杂约束求解器可在不改变 API 语义的情况下替换当前算法。

当前聚合限制为最多 32 支球队、12 个场地和 31 天日期范围，避免同步事务和响应无界增长。更大赛事、分组阶段和结果驱动晋级需要后续独立设计。
