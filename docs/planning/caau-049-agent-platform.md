# CAAU-049 业务智能体平台分阶段计划

状态：A 架构选择已确认；B1 查询与单场调整预览已于 2026-09-22 完成本地实现和隔离数据库验收。采用 NestJS + LangGraph.js + 千问适配层 + 原业务权限/确定性规则 + PostgreSQL checkpoint。B1 不保存或发布赛程；真实模型、小程序和真机仍待验证。

## 目标

把自然语言变成可审阅、可授权、可执行、可审计的业务动作。首个垂直场景为赛程查询和草稿调整，复用 CAAU-042 的确定性赛程 API，不另建排程规则。

产品方案见[业务智能体方案](../product/agent-platform-plan.md)，技术边界见[ADR-0019](../adr/0019-agent-orchestration.md)。

## A：产品与权限确认

- 确认首个入口、首批角色和赛程能力矩阵；
- 确认草稿调整与发布的确认规则；
- 确认 Agent 对话、轨迹和敏感字段的数据处理要求；
- 盘点现有 schedule 权限并设计拆分，不在提示词中模拟权限。

## B：只读 Agent 基座

- 新增服务端 `ai` 模块、模型供应商适配、会话/turn/轨迹和调用预算；
- Web 智能体侧栏，携带当前页面/赛事上下文并流式展示；
- 首批只读工具：有权赛事和当前赛程；
- 验证越权资源 ID、撤权、会话过期、提示注入、超时和模型降级。

### B1：查询与单场调整预览（本地完成）

目标：输入“把周六第二场改到周日 10 点”，正确定位有权赛事与场次，展示修改前后及确定性冲突结果，不保存赛程。

1. 核验并固定 LangGraph.js、checkpoint 和模型适配依赖与 Node.js 24.20.0 的兼容性；先连通一个已配置的千问或混元模型。密钥仅在服务端忽略配置中设置。
2. 建立 Nest `ai` 模块、用户绑定会话、LangGraph 状态图、调用预算和最小脱敏轨迹；数据库连接及 checkpoint 初始化归 `@caau/database`。
3. 注册赛事列表、赛程读取和纯调整预览工具；赛事列表沿用 `listCompetitionEvents` 的业务范围，具体读取再次鉴权。预览复用 scheduling 算法与校验，不调用会保存草稿的 generate。
4. 先定义 Nest DTO/控制器，再生成客户端；建议 Web 赛程页提供对话与预览卡，后续小程序复用同一 API。入口建议不视为用户已确认的小程序排期。

验收：多场匹配需选择；跨赛事/跨用户 thread 访问被拒绝；停用或撤权立即生效；模型超时不改变数据；预览前后赛程 revision、版本及业务写审计不变；真实模型连通、API、浏览器和微信真机结果分别记录。模型凭据缺失时可验证模拟模型下的业务链路，但不能称真实模型接入完成。

实际交付：新增 `ai` 模块、会话/turn/任务模型、`caau_agent` PostgreSQL checkpoint，以及由鉴权、意图增量解析、赛事/场次定位、缺参等待、确定性预览和结果返回组成的 LangGraph 业务图。L1 用结构化 event/match 字段配合近期对话和摘要；L2 保存 owner/目标/步骤/逐字段条件/待补字段/候选 ID/资源/baseline/任务 revision/预览/有效期/checkpoint。同一任务稳定复用 task/thread，显式新任务与赛事切换清除旧条件；来源星期/序号变化重新定位 match，明确日期与目标星期互相覆盖，绝对字段变化及相对时间跨日/跨周按规则清理派生字段。恢复逐次校验当前身份、所有历史任务资源权限、版本及期限，模型前和业务读取/预览前均有授权关卡。L3 仅记录未来明确偏好与有来源知识的边界，没有建空表或向量库。新增纯 `preview-adjustment` 能力，复用 scheduling 校验，不调用 generate。Web 赛程页提供对话、歧义选择、前后差异卡，以及仅总部超级管理员可见的安全模型状态和显式连接测试；小程序入口另行实施。

实际验证：固定依赖已核验 Node 兼容性；冻结安装、`contract:generate/contract:check`、完整 `check`、三端 `build`、包/应用测试、HTTP 联调和 Web E2E 均纳入回归。B1 初版隔离 PostgreSQL 最终为 70/70、0 跳过。流程补强专项新增“三轮调整”、连续赛事/场次候选选择、切换赛事、任务并发 200/409、撤权后消息 403 且模型调用零增长、等待补参后实际停服重启继续同一 task/thread、checkpoint 不含 token/消息原文，以及赛程 row/matches/version 不变。补强首轮为 66/70（测试漏传模型计数回调导致专项中断，并连带授权未恢复；末尾浏览器因此失败）；第二至第五轮均为 68/70，Agent 专项已通过，继续定位出模拟解析器把“周三十点”连读为 30 点，而非权限或流程恢复故障；修正按星期分词及增加回归后，最终完整 `db:test` 为 70/70、0 跳过；最终冻结安装、契约检查、完整 `check`、三端 `build`、64 项包/应用测试、1 项 HTTP 联调及 Web E2E 11/11 通过。当时未配置或调用真实千问。后续用户报告同一 `qwen-plus` 已连接成功，并实测带字段说明和来源/目标示例的方案能正确提取来源场次；仓库已按该方案修正并增加不进入默认 CI、无数据库访问的 `agent:qwen:test` 手工命令。本次执行环境未注入凭据，故只记录用户实测与本机模拟/业务回归，不声称本机真实模型通过。小程序未增加入口，微信工具或真机未运行。

## C：赛程草稿工具

- 细分 schedule read/generate/adjust/publish 能力并回归现有 Web；
- 接入生成候选和逐场调整工具；
- 建立影响预览、一次性确认票据、commandId、expectedRevision 和 409 重新核对；
- 暂不开放 Agent 发布。

首个可写闭环只开放单场调整：确认票据绑定实际 actor、赛事、场次、参数摘要、基线版本及有效期；恢复前重新鉴权。补足持久命令回执，验证重复确认、进程重启及提交后断线不会重复修改；409 要求重新预览确认。整套生成后接入，先补 expectedRevision，不能复用现有无版本保护的生成命令直接覆盖。

## D：受控发布与评测

- 接入专门 `schedule.publish` 能力和独立确认；
- 建立固定多角色、多赛事、多表达评测集及工具轨迹评分；
- 真实 PostgreSQL/API/浏览器验证与人工操作结果一致；
- 确认生产模型配置、限流、成本预算、日志脱敏和故障降级后再开放。

## E：业务扩展

材料、申请、物料、球队等按“已有稳定领域 API → 权限/风险矩阵 → 只读 → 草稿/写入 → 评测”的顺序逐项接入。不得因为模型能描述某项业务就自动生成通用写工具。
