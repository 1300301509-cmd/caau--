# 角色与权限矩阵（CAAU-008）

状态：原型静态事实 + 正式系统建议，业务授权尚未确认。来源标记与 `P:` 路径定义见 [功能清单](feature-inventory.md)。原型六种角色不等于用户已确认六种正式岗位；不复制演示账号、名单或凭据。

## 1. 原型实际授权

来源：`P:server.py:ROLE_MODULES/allowed_event_ids/handle_api_get/handle_api_mutation`（75–92、542–547、677–855）、`P:platform.js:configureIdentity`、`P:app.js:roles`。下表“有”指代码路径，不指运行验收。

| 原型角色 | 查看 | 创建 | 修改 | 审核 | 实际数据范围 |
| --- | --- | --- | --- | --- | --- |
| 总部 hq | 全部赛事；财务、运营、任务、门户、资料、管理、助手 | 赛事；运营证据 | 赛事、财务、节点、任务、交付项、赛后名次 | 无独立审核动作；可直接写状态 | hq 或 scope 含通配符可取全部赛事 |
| 内部团队 team | 范围内财务、运营、任务、门户；资料/助手 | 运营证据；没有创建任务/赛事接口 | 财务、节点、任务、交付项、名次 | 同上，无审核人与提交人分离 | 用户 event_scope，不是按任务负责人过滤 |
| 城市承办方 organizer | 范围内完整财务、节点、任务 API、门户；资料/助手 | 运营证据；本地球队新增不算共享创建 | 节点、任务、交付项、名次；不能 PATCH 财务 | 可以直接写“已验收/已完成”等状态，不是合规审核 | event_scope；非依据 organizer_id 动态授权 |
| 参赛俱乐部 club | bootstrap 赛事范围、资料、助手；clubs/overview 旧页面 | 无相应业务 API 创建 | 无球队/教务 API 修改；外部系统未知 | 无 | API 仍依赖 event_scope；本机构隔离仅有描述/外部入口，未证实 |
| 品牌赞助商 sponsor | bootstrap 范围、资料、助手；赞助旧展示页 | 无赞助 API 创建 | 无权益 API 修改 | 无品牌确认动作 | 合同范围没有实际授权查询实现 |
| 裁判员 referee | bootstrap 范围、资料、助手；裁判旧展示页 | 执法记录仅 localStorage | 未见裁判档案 API | 无复核动作 | 本人过滤没有对应业务 API；本地演示不是本人隔离 |

所有登录用户均可 GET 资料列表并经下载路由取有源文件的资料，代码未按 audience 过滤。bootstrap 返回赛事不等于拥有该赛事所有模块操作权。列表中的越界赛事筛选被静默滤除；详情更新多返回 403。上述行为为原型事实，不作为正式 API 错误策略承诺。

### 与页面/蓝图不一致的重点

1. 承办方前端没有协同中心菜单，但 tasks API 仍允许访问和更新；总部“角色预览”只改展示，实际 API 仍用总部身份（`app.js:roles`、`platform.js:configureIdentity`）。
2. `permissions_matrix.json` 声称按机构、合同和本人隔离，且列出报名审核、课程课消等；实际 CAAU API 只见模块白名单和赛事范围，不能沿用 JSON 作为实施完成证明。
3. 资料 API 虽认证，但无业务可见性过滤，静态模板路径可匿名读取；“权限下载”文案不证明私有文件隔离（`server.py:serve_static/send_material`）。
4. update_record 字段白名单不是状态机；承办方可修改任务定义和节点负责人，可直接置完成/验收。上传证据只检查传入赛事，没有核验节点属于该赛事（`handle_api_mutation/upload_evidence`）。
5. 本地报名、执法、任务和 SOP 键没有完整用户/赛事隔离；页面电话遮罩不等于导出脱敏（`app.js:bindDynamic/readOrganizerTeams/exportOrganizerTeams`）。

**建议：不复用原型授权代码、演示账号和 localStorage 作为正式权限底座。** 来源：上述静态风险及 [repository.md](../architecture/repository.md) 的服务端职责约束。

## 2. 正式系统候选角色矩阵

以下全部为**建议/业务待确认**，依据原型六类角色、蓝图 §三与 [requirements.md](requirements.md) H-003。`—` 表示建议默认拒绝，而非永不建设。查看、创建、修改、审核必须是独立权限；同一人可在不同组织/赛事担任不同职责，不能只在 users 上保存唯一业务角色。

| 候选角色/职责 | 查看 | 创建 | 修改 | 审核 | 数据范围 |
| --- | --- | --- | --- | --- | --- |
| 总部赛事管理员（首闭环） | 授权赛事、承办组织、任务、材料及审计 | 赛事、赛事授权、任务分配 | 赛事草稿、任务要求；提交后要求变更须版本化 | 仅另获审核权限才可审核 | 显式授予总部全局或指定赛事；不自动拥有全部财务/个人资料 |
| 总部审核员（首闭环职责，可与管理员同账号但按动作检查） | 指定赛事的提交版本、附件、历史 | 审核记录 | 不覆盖提交材料或旧审核记录 | 通过/退回；不可审核本人提交 | 审核任务/赛事范围；只返回所需字段 |
| 内部执行团队（后续扩展） | 分配任务和必要赛事上下文 | 自己负责事项的草稿/证据 | 自己草稿/退回稿，不改他人任务和财务 | —；另行授权审核职责才可执行 | 分配赛事 + 任务关系；财务独立授权 |
| 城市承办方经办人（首闭环） | 授权赛事、分给本机构的任务、相关模板、自己提交及审核结果 | 材料草稿、附件、提交版本 | 草稿/退回稿；不得改总部任务要求或审核结论 | — | 显式赛事授权 ∩ 当前机构成员关系 ∩ 任务承办机构；不默认全赛区敏感数据 |
| 俱乐部负责人/教练（后续候选） | 本机构授权球队、当次报名与已发布赛事信息 | 球队/报名草稿 | 负责球队或报名草稿；名单修改遵守锁定规则 | 不审核自己报名 | 机构/球队关系；未成年人资料最小化；普通教练不默认看全机构学员 |
| 赞助商联系人（后续候选） | 自己合同约定的权益、证据和约定指标 | 确认意见/反馈 | 自己未提交意见，不改运营交付事实 | 仅合同授权的权益确认，不等于赛事/财务审批 | 合同参与关系 + 权益范围，禁止跨品牌 |
| 裁判员（后续候选） | 本人档案、指派场次、本人反馈 | 本人资质材料、执法报告 | 本人草稿；不改已审纪律和比赛最终结果 | —；主管复核需独立职责 | 本人 + 指派比赛；申诉人身份等敏感字段另控 |
| 系统权限管理员（基础运维职责建议） | 账号、成员、授权及安全审计 | 受控账号邀请、授权记录 | 禁用/撤权/成员调整 | 不因技术管理员身份取得业务审核权 | 账户与授权管理范围；业务数据按另外授权 |

首闭环暂不建设开放注册、复杂审批授权链或通用角色配置器。建议由受控管理入口建立内部人员、承办机构与赛事授权，后续再扩展邀请流程；具体账号准入方式在 CAAU-004 细化。

### 首闭环对象级权限（可直接转为测试用例的建议）

| 对象/动作 | 总部赛事管理员 | 总部审核员 | 承办方经办人 |
| --- | --- | --- | --- |
| 赛事查看/创建/修改 | 授权范围内可；创建需显式权限 | 查看范围内上下文 | 仅查看被授权赛事的必要字段 |

## 3. 横切控制与待确认登记

全部为**工程建议**：后端同时判断会话、操作权限、数据范围与状态；默认拒绝。列表、详情、统计、附件、导出和后续 AI 工具使用同一范围服务；不相信前端 role、organization_id、event_id 或对象 ID。文件先授权上传，绑定时验证所有权、对象归属和上传完成状态；临时下载地址短期有效，撤权后不可取得新地址。权限变更/禁用后下一次业务请求应生效，已签发地址残余有效期纳入验收。

| 待确认编号 | 内容 | 处理顺序/临时建议 |

| Q-P01 | 谁负责最终材料验收；总部与内部团队是否有不同审核层级 | 首闭环确认后细化；先建议单级指定总部审核员、禁止自审 |
