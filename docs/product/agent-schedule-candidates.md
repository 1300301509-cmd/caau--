# CAAU-064：已确认需求 → 整套候选赛程预览

来源：[用户明确提出的 CAAU-064 目标与验收](../planning/roadmap.md)。需求采集、版本、来源和确认沿用[CAAU-063 规格](agent-schedule-planning.md)；实现取舍见 [ADR 0026](../adr/0026-agent-whole-schedule-candidate-preview.md)。确认需求**不是**赛程执行许可。

## 生成前

- 必须选本人已确认且仍有效的独立需求版本；读取有权赛事、赛程基线、参赛记录和配置来源。单循环要求按当前全部有效 `EventTeam` 各两队一场，其他赛制不静默降级；未提供完整日时段、日期、场地、场次时长、场地缓冲及球队最短休息时应停在输入检查，不补建议值为业务规则。已有赛程配置可作为明确来源，若与确认日期/参赛名单冲突，须重新核对并显式填写全部配置。当前赛程基线 0 表示未保存任何正式赛程。
- 当前不重排已发布（可能已开赛/完赛）或淘汰赛基线；旧草稿中开始时间已过或本版本有工作人员安排的比赛必须明确列为固定，其它旧场次也需明确勾选固定范围（允许用户明确选择空集）。系统暂无结构化完赛标记，不能借预览声称已验证真实现场进度。
- `MUST ONLY`：该队本次所有比赛均在指定日期/时段内；`MUST BLOCK`：不能与禁赛时段重叠。`AVAILABLE` 是可安排的描述，**不是**其它时间均不可用；若将其标为 MUST、却未说明只能在该时段，候选计算无法判定比赛安排硬约束，应先修订为明确 ONLY/BLOCK 或 PREFER，不忽略后声称全部硬条件满足。同级 PREFER 尽量满足并逐条报告未满足。单循环两队本就必交手，未明确“提前”的轮次/时刻语义时，不接受 MATCHUP 作为优化目标，先修订需求。不能为了偏好增删比赛或降低硬条件。

## 展示及后续

只展示“候选预览，尚未保存”的周赛程；按北京时间逐场列出候选时间/场地及对应旧场次，汇总受影响场次、来源、基础 revision、需求 revision、偏好状态和校验问题。`FOUND` 是当前配置下经确定性校验的合规候选；`PROVEN_CONFLICT` 限于明确必要条件冲突；`SEARCH_LIMIT` 是预算或当前搜索顺序内未找到，不等于无解。恢复逐次重新鉴权，需求、基线、参赛或本版本工作人员安排改变，原候选 `STALE`；不能拿旧结果推进保存或发布。没有候选 → 404；前端不显示旧信息。候选存在独立表，不新增正式赛程版本、票据、回执，不暴露保存和发布入口。

Web/Taro 都可从已确认需求卡单独进入候选输入与预览；小程序 weapp 构建/Node 替身不等于微信工具或真机实测。Studio 独立 Graph 中仅有明确输入后的 `generate_candidate → validate_candidate` 节点，无确认/正式写入节点；官方页面登录后人工执行另记。真实千问负责需求理解，程序负责安排与校验；模拟、隔离数据库/浏览器和真实千问验收必须分别记录。现场场次进度、正式赛制/轮次/主客规则与共享场地资料尚待确认，不应把合成数据或实现限额登记成业务规则。
