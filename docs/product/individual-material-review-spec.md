# 单份办赛材料与共享审核规格

状态：2026-09-15 用户确认；CAAU-011 仅交付规格，代码尚未改造。本文件取代旧规格中的固定材料清单、整包审核和指定单一审核员规则；旧功能及验收记录不代表本规格已实现。

## 当前范围

本轮仅处理承办方向总部提交办赛材料。总部指定承办方，填写所承办大区赛的基础信息。承办方可在自己的赛事内自行新增材料，不要求先完成固定五项清单；材料单独提交、单独审核，互不等待。任意材料指业务名称和类别开放，不代表允许任意文件格式或大小，也不允许跨赛事越权。

现有总部模板能力保留；模板不得成为自由新增材料的必选前提。本轮不建设模板库、报名、支付、俱乐部教务或其它经营模块。

## 状态与操作

| 当前状态 | 操作 | 结果 |
| --- | --- | --- |
| 待提交 | 承办方保存草稿 | 仍为待提交 |
| 待提交 | 承办方正式提交 | 待审核；生成不可变 V1 |
| 待审核 | 有权总部审核员明确点击开始审核 | 审核中；记录人员和时间 |
| 审核中 | 有权总部审核员通过 | 审核通过 |
| 审核中 | 有权总部审核员填写退回原因、修改要求并退回 | 退回修改 |
| 退回修改 | 承办方修改草稿 | 仍为退回修改；保留旧提交 |
| 退回修改 | 承办方重新提交 | 待审核；生成 V2、V3 等 |

状态由后端业务操作驱动，不提供任意手改状态。打开详情不等于开始审核。审核通过后不提供隐式重开或修改已通过版本。每份材料有独立版本及历史，不覆盖之前的附件、提交人、审核人或时间。

## 共享审核与权限

- 正式提交后进入该赛事有权总部审核员的共享队列，无需先指派某一人。
- 其它有权审核员可以查看并继续推进审核；开始审核记录行为，不构成独占领取或永久锁定。
- “共享”仅指已获赛事审核权限的总部审核员，不扩大为所有总部账号或所有赛事。系统管理员不自动获得业务资料；承办方不能审核自己的材料。
- 每次开始审核、通过、退回以及提交、重交均记录实际操作人、服务器时间、目标材料和提交版本、前后状态；退回还记录原因与修改要求。
- 同一版本的相互冲突操作只能有一个成功。后来请求明确返回最新状态与冲突提示，不覆盖先前结果。状态与审计同事务保存，不能发生状态成功而审计丢失。
- 私有上传、绑定、模板及附件下载仍由后端鉴权；实时订阅不得绕过组织、赛事和材料访问范围。

## 自动同步页面

正常在线时无需手动刷新：承办方提交后总部队列自动出现材料；开始审核、通过、退回后，有权且正在查看的页面自动更新状态、操作人、时间和历史。

技术验收要求：仅在事务提交成功后通知；重复或乱序通知不得让状态倒退；断线显示连接状态，重连和小程序回到前台时重新获取权威状态；会话失效或撤权后停止受保护数据访问。更新状态不得覆盖用户尚未保存的输入。页面实时更新不能替代后端并发控制，也不等于微信订阅消息或后台离线通知。

传输方案由 Pi 根据现有 Nest、Web、Taro 能力提出并记录 ADR，再实现；不预先认定某一协议已可用。报告实测同步延迟及断线恢复表现，不承诺零延迟。

## 既有规则与迁移边界

继续遵守 [需求登记](requirements.md) R-014～R-019 中未被本规格替代的规则：逾期可存草稿、延期后才可提交；同机构交接留历史并撤销旧权限；禁止跨机构直接搬迁；不可变版本、私有文件和模板快照保留。新单份材料如何关联现有任务的截止时间、指派和模板，应先在技术设计中明确；不得擅自取消这些约束或把既有任务复制成互相矛盾的数据。

旧整包提交不能伪装成当时已逐份审核。采用追加迁移和明确兼容策略，保留原记录、对象与历史迁移 checksum；若转换会损失原审核含义，保留旧版只读历史并为新版提供独立入口。具体映射须在实现前写入设计。

## 验收

1. 两赛事、两承办方、两名有权总部审核员；另设无权总部账号。列表、详情、写操作、文件、实时订阅均验证隔离。
2. 承办方自由新增至少两份不同材料，提交其中一份不依赖另一份；分别跑通通过和退回重交。
3. 审核员甲开始，乙继续通过或退回；历史准确显示每步实际人员。无权账号和自审被拒绝。
4. 两审核员同时对同一版本发出相反结论，只产生一个有效结果；另一端收到冲突和当前状态。重复提交不产生重复版本。
5. 多会话页面无需手动刷新完成提交、开始、退回、重交、通过的同步；覆盖断线重连、重复/乱序通知、撤权、会话失效和编辑输入保留。
6. 旧 V1/V2、模板、附件、数据及迁移 checksum 保留；重启后新旧历史均可读且不串权。
7. 使用真实 PostgreSQL、HTTP 和浏览器验证。小程序构建、开发者工具、真机分别记录；资源缺失时不得把浏览器联调当微信验收。

## 后续产品边界（已确认，非本轮实现）

- 俱乐部与球队在当前业务语义上指报名主体，可报名任意承办方的赛事，不是永久归属于单一承办方。数据库实体及外部 ID 映射待接口设计。
- 承办方仅能看该俱乐部与自己所办赛事有关的资料；俱乐部之间数据隔离。
- 报名由另一个小程序负责，接口后续由用户提供；不重复开发报名入口。
- 后续展示人数、球队、组别、教练联系方式、缴费情况及球队资料审核情况；球队审核流程尚未细化，本文件五状态只约束承办方办赛材料。
- 缴费现阶段人工标记未缴费、已缴费、已退款，不代表 CAAU 实际收款或退款；本轮不实现。
- 赛事信息变更由承办方申请、总部确认；报名后变更需通知相关俱乐部，但不由 CAAU 发送。外部通知责任方及接口待明确，不擅自增加推送功能。
