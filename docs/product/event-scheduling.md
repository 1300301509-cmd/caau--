# 赛程编排（CAAU-042）

## 产品原则

赛程编排的底层能力独立于交互入口。当前 Web 工作台直接调用生成、校验、调整和发布接口；未来产品智能体理解自然语言后，也只能调用同一套接口并遵守相同权限、版本和发布门槛。智能体不直接写数据库，也不能绕过人工发布。

第一版支持：

- 单循环：每两支球队比赛一次；奇数球队自动轮空一轮。
- 单败淘汰：支持 2、4、8、16、32 支球队；后续轮次以“第 N 场胜者”作为参赛来源。
- 编排条件：本赛事有效球队、日期范围、每日可用时段、一个或多个场地、每场时长、换场缓冲和球队最短休息时间。
- 人工调整：逐场修改比赛时间和场地，保存后重新运行完整校验。
- 版本状态：算法生成和人工调整均为待发布；零冲突后可发布。已发布方案再次生成或调整会形成新的待发布版本，旧发布版本继续保留。

申请办赛阶段不填写具体开赛时间，不影响本模块为每一场比赛安排日期和时间。

## 数据与校验

赛程只引用 `EventTeam`，并把当时的对阵显示名称保存在方案中；不会动态读取小程序球队主档案。球队退出当前赛事后，已发布版本保持原记录，但当前工作台立即显示“球队不可用”，要求重新生成或处理后才能再次发布。

当前校验包括：

- 所有场次均有比赛时间和场地；
- 时间位于配置的日期、每日时段内，场地属于当前可用场地；
- 同一场地的比赛不重叠；
- 已知球队的比赛不重叠并满足最短休息时间；
- 淘汰赛后续轮次晚于全部前置比赛，并满足最短休息时间；
- 选中球队仍属于本赛事且状态有效。

算法无法满足全部条件时保留候选方案，并逐项说明未安排或冲突原因，不自动缩短比赛、减少休息时间或扩充场地。存在任何冲突时，服务端拒绝发布。

## 权限与并发

总部超级管理员、持有当前赛事有效管理授权的赛事经理，以及该赛事有效承办机构中持有有效办理授权的承办人员可以读取和操作赛程。审核员、仅有基本信息查看权的人、无当前赛事授权的经理和球队账号不能操作。

所有生成、调整和发布均使用命令 ID 防止重复提交，并携带修订号避免多人覆盖。数据库保存不可变版本，运行账号不能更新、删除版本，也不能物理删除当前赛程。

## 当前限制

第一版不包含分组循环、双循环、交叉淘汰、种子位、主客场偏好、裁判资源、跨日特殊时段、轮空的可视化配置、比赛结果晋级回填和自然语言对话入口。时区固定为北京时间。单败淘汰暂要求球队数量为 2 的幂；不自动安排附加赛或轮空签位。
