# CAAU-005 第三段：页面与交互方案

准入：从干净 `4b587b3` 建立 `codex/caau-005-workflow-ui`，保留前三次迁移与数据。依据 [首版规格](mvp-material-review-spec.md)、[操作手册](../runbooks/material-tasks.md)。本轮先记录设计，再实现。

## 结构与操作路径

- 总部 Web 保留 `/workspace` 的账号登记、建赛事、指派、要求、发布；增加跨赛事待审核队列，进入任务后查看执行状态、当前有效截止、不可变提交版本、附件及审核历史。
- 审核员针对当前待审版本整包通过，或选择问题材料逐项填写原因与修改要求后整包退回；确认框显示版本及动作影响。历史版本只读，不提供编辑内容入口。
- 本赛事管理员在详情执行延期、同机构交接、关闭；展示新截止/原因、目标经办人/撤旧权影响、关闭后不再办理的确认信息。后端仍为最终权限依据。
- 小程序仅“待办、赛事、我的”：待办卡片 → 任务详情 → 材料说明/填写区/私有附件 → 保存 → 确认正式提交；退回查看材料问题，在新草稿修改再提交。赛事页按赛事筛选任务；我的提供明确标注的本地测试身份入口，不冒充微信登录。
- 浏览器闭环增加承办身份的 Web 联调办理界面，消费相同业务契约；这不是微信运行时验收。小程序仍以 Taro 原生页面实现，不跨应用引用源码。

## 状态与失败反馈

- 顶部显示 EDITING（有退回则待修改）、SUBMITTED、APPROVED、CLOSED，版本、截止和责任；状态配文字，不能只靠颜色。
- 上传经过读取/上传/确认，只有确认成功的 ID 进入本地草稿；失败保留错误提示，阻止正式提交，允许明确移除失败项或重新上传。全部文件最终由后端再次校验。
- 保存、提交及上传期间禁用冲突操作并用同步锁防重复点击。正式提交固定幂等键和草稿 revision；未知网络结果保留待重试命令，不能另起新键伪造再次提交。
- 草稿 409 保留当前输入；单独读取并展示最新草稿供核对，只有用户明确选择“保留我的输入，以最新修订继续保存”才更新基础 revision。不自动替换用户输入；交接/撤权禁止继续写入。
- 逾期可保存，明确提示须总部延期；最终服务器时间决定是否提交。通过/关闭只读；退回不自动延期。切换/离开未保存输入需确认。

## 视觉与可访问性

使用 ui-ux-pro-max 检索的 Minimalism/Swiss 风格作为参考：浅灰底、白色卡片、信任蓝主色、深色正文、清晰分区；保持现有 AntD 与中文系统字体，不引入外部字体请求。检索的营销 Hero 模式不适用后台，不采用；进一步 product 检索落到 IoT 也不匹配，页面结构采用仓库现有后台模式及 skill 通用准则，不声称命中了专用业务模板。React 栈检索的异步错误显式反馈准则适用并采用。手机单列卡片、44px 以上触控区、底部安全区、明确字段标签；错误可见且可重试，降低动画，长 UUID/文本换行。

## 上传能力与明确缺口

以服务端能力契约获取 txt/pdf/png/jpg/jpeg、10 MiB 技术上限，配置与上传均校验；服务端保存/发布再拦截超能力要求，保留旧数据不暗改。正式业务大小仍由总部在能力内配置。模板仅版本标识，**真实模板管理/授权下载列入首版待办**，不放无效下载按钮。

## 验收计划

真实隔离 PostgreSQL/API/浏览器：发布→提交→通过；发布→提交→退回→修改→V2→通过；附件上传失败、草稿冲突输入保留、逾期保存提示、交接后旧人拒绝与新人接管。截图使用合成身份/材料，不含会话。另跑检查、三端构建、测试及原有迁移/权限回归。微信登录、开发者工具/真机、生产存储/扫描和远程 CI 单独记录，缺资源不阻塞页面开发。
