# CAAU-034 小程序办赛流程

用户明确的新层级：`首页 → 我要办赛 → 申请比赛 / 材料提交 / 办赛进度`。“我要办赛”是可点击跳转的首页卡片，不在首页展开三个子模块；底部首页/我的保留。

## 阶段与权限

1. 申请比赛：填写赛事名称、比赛地点、开始日期、联系方式和选填补充说明。新建申请使用简表v2，不要求营业执照、场地照片及机构经验作为申请前置；已有v1申请和不可变历史沿用原规则。
2. 总部允许申请后进入材料阶段。没有获批赛事时，材料入口仍可进入，显示“当前没有通过申请的比赛，请联系相关工作人员哦”。七项必填沿用CAAU-033。
3. 材料审核通过后进入“合同签订”。合同在线下办理，小程序不签署合同。
4. 授权总部工作人员确认线下合同已签订后进入“批准办赛”。承办方不可操作，材料未通过不可越级批准，重复确认不重复记录。确认保留原操作人和服务端时间，不提供撤销或改写入口。

联系方式默认采用姓名和大陆手机号；补充说明选填。已询问用户是否只需要手机号，以及合同确认是否需要编号/凭证；未收到进一步修改时按最小确认操作实现，不提供在线签约。工作人员首版沿用有效总部审核授权及超级管理员权限，不自动给普通账号新增权限。

## 进度

服务器从原申请、对应赛事材料及合同确认记录推导四阶段，不由客户端写任意阶段。申请/材料被退回时保持对应阶段并显示补充意见；驳回仍显示驳回，不自动进入下阶段。页面打开每3秒串行同步，后台停止；同步失败标明内容可能过期，不显示虚构进度。合同确认后承办方在下一次同步看到批准结果。

## 验收

验证新简表可无附件提交且手机号/时间必填，旧版本仍按原规则；无获批赛事空态、实际页面跳转；权限隔离、合同前置条件、重复确认、历史不可变和跨身份进度同步。构建/数据库/浏览器、微信开发者工具、真机分开记录。

后续用户修订：申请简表仅选择开始日期、开始时间，不再填写结束日期/结束时间。新简表提交不要求结束信息；材料阶段赛期及已有历史版本不在本次修改范围。

最新用户修订：申请比赛也不再填写开始时间，仅保留开始日期；联系方式、地点及选填补充说明保留。新简表前后端均不要求具体时刻。

## CAAU-037 申请填写入口调整

- 用户确认：申请比赛进入即填表，直接提交；不再要求先建立申请草稿。中途退出保留草稿，下次进入询问恢复或重新填写。
- 新申请输入按已认证用户及机构保存在当前设备；不包含会话令牌。选择重新填写清除该份本机暂存，不删除已有服务器申请；换设备不能恢复尚未提交的本机输入。
- 首次点击提交才调用既有创建、保存、提交接口。发送前持久化幂等键；成功清除本机草稿，网络失败保留重试信息；检测共享草稿变化时转到办赛进度核对，不覆盖其他经办人输入。
- “本机构申请”和状态筛选放入办赛进度；通过继续填写、补充申请、查看申请进入指定记录。已有服务器草稿及补充版本保留原保存、冲突核对和提交流程。办赛材料页面不变。
- 本轮开发者工具以本地测试身份验证直接表单、退出后恢复及重新填写；恢复弹窗的选择由自动化桥模拟。未新增演示申请，未执行本轮真实提交或真机验收。

## CAAU-038 小程序办理页视觉

- 三个办理页共用 CAAU 品牌页头及暖白内容底色；申请/材料/进度分别用浅杏、浅绿、浅蓝灰轻量区分，墨绿为主操作色。
- 新申请按比赛信息、比赛场地、联系与补充分为三张卡片；表单使用浅底输入区、明确标签和原生日期/地区选择器，保留直接填写及本机草稿恢复。
- 材料页改为原生赛事选择器，当前材料已打开时省去重复打开按钮；材料列表/筛选通过“查看材料记录”展开，保留历史访问；当前材料摘要显示名称、机构及提交版本，去掉内部 UUID 与修订计数。
- 办赛进度采用横向滚动状态筛选、状态标签及连接的四阶段节点，保留记录展开、补充申请和批准动作。长表单与记录自然滚动，提交按钮留在内容末尾，避免固定操作栏遮挡键盘和输入。
- 样式限定在办理页，未改变首页、登录、总部 Web 及业务接口。按钮/输入区约 44–46 逻辑像素高（750 设计稿），底部保留安全区。
