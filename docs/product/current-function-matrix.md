# 当前产品功能清单：总部、承办方与俱乐部

状态：CAAU-013 现状梳理，2026-09-15。本文区分正式工程的实际证据、平台待验、已确认需求、未确认业务和外部系统责任；不把原型页面、建议方案、源码存在或构建通过写成业务已完成。

依据：[需求登记](requirements.md)、[单份材料规格](individual-material-review-spec.md)、[产品原型清点](feature-inventory.md)、[CAAU-012 计划与证据](../planning/roadmap.md)及当前正式源码。微信小程序注册和依赖真实 AppID 的验收已按用户当前指令暂缓，不取消原待办。

## 1. 状态口径

| 状态 | 本文含义 |
| --- | --- |
| 已实现并实际验证 | 正式仓库已有实现，且至少经过真实 PostgreSQL/API、独立浏览器或官方开发者工具中与该结论匹配的实际检查；每项注明验证层 |
| 已有源码但尚未平台验证 | 代码和自动测试/构建存在，但所需微信能力、正式身份、HTTPS或真机证据不足；不能写成微信可交付 |
| 已确认但未实现 | 用户已经确认业务方向或验收要求，但当前正式模型、接口或页面缺失或仅覆盖一部分 |
| 仍待业务确认 | 只有原型、历史建议或未细化方向；不能据此建立正式字段、状态或权限 |
| 外部报名小程序负责 | 已确认不在CAAU重复开发的报名入口；接口、数据主责和异常协作仍须另行确认 |

“实际验证”不等于生产、远程CI、独立安全审计或全部异常场景通过。正式工程中的本地opaque会话也不等于微信登录。

## 2. 总部

### 2.1 已实现并实际验证

| 功能 | 当前能力 | 实际证据与边界 |
| --- | --- | --- |
| 内部账号、组织、成员角色和赛事授权底座 | 系统管理员可经Web/API登记内部用户、组织和成员角色；授权、停用、会话撤销及审计由服务端控制；系统管理员无隐式业务资料权限 | CAAU-004/005真实PostgreSQL/API及权限反例通过；当前只是内部/本地身份体系，不是微信用户体系 |
| 创建与查看赛事 | 有权总部赛事管理员可在Web `/events` 创建赛事并查看授权范围内赛事和详情 | CAAU-018真实API、PostgreSQL及Chromium流程通过；赛事目前只有名称、说明、创建人和创建时间，页面明确不把访问授权显示成承办关系 |
| 创建旧整包材料任务并指定承办 | 在赛事下创建任务草案，选择承办机构、经办人和单一审核员；配置要求/模板后发布 | CAAU-005真实浏览器、API和数据库闭环通过；这是任务级指派，不是赛事级唯一承办方关系 |
| 材料要求、模板和发布快照 | 发布前配置截止、要求、格式/大小和可选私有模板；发布后Requirement V1及模板关联只读 | 真实文件字节、权限下载、迁移保留及浏览器流程通过 |
| 旧整包审核及管理动作 | 查看不可变提交/历史，整包通过或按材料退回；支持延期、同机构经办交接和关闭 | 真实API/浏览器及并发、权限、重启回归通过；旧流程在启用新版单份通道后只读 |
| 新版单份共享审核 | `/materials`共享队列、明确开始审核、通过/退回、甲开始乙接续、实际人员/时间、不可变V1/V2和冲突保护 | Web独立多会话、真实PostgreSQL/API通过；官方游客模拟器与Web配合跑通一条V1退回/V2通过主路径 |
| 旧数据兼容 | 旧整包提交、附件、模板和审核历史继续按原权限读取，不伪造成逐份审核 | 追加迁移升级、checksum、字节和重启验证通过；未reset或改写历史迁移 |

### 2.2 已有源码但尚未平台验证

- 总部审核本身定位在Web，不要求搬入小程序；因此不存在“总部小程序待验”成果。
- Web/API能力尚未经过生产身份、生产存储、远程部署、长期轮询负载或独立安全评审；这些属于环境/发布验证，不应改写为功能缺失或已完成。
- 事件授权停用、新版任务创建/启用等接口已有源码及真实API测试，但新版单份任务创建和授权管理尚无完整总部Web操作入口；当前演示任务由受控命令追加。

### 2.3 已确认但未实现

- 承办申请首版表单固定为赛事名称、开始日期、结束日期、赛事地点；正式提交四项必填且结束日期不得早于开始日期。资料固定为必交营业执照、简介（办赛经验）、现场照片和选交其他文档；格式、大小、数量仍只是实现建议，不新增业务必填项。总部通过独立申请审核权限共享处理承办申请并遵循已确认审核规则。通过后须原子创建正式赛事、登记申请机构承办关系，并为当时有效申请经办人逐人创建独立基本信息只读授权；不得复用宽泛角色，查看权不含赛事修改、审核或材料任务办理。获批不创建材料任务，总部后续创建并指派、沿用现有任务权限。当前没有相关模型、接口或页面，设计见[赛事承办申请产品规格](event-hosting-application-spec.md)。
- 总部填写完整的赛事基础信息并指定承办方：当前仅实现赛事名称/说明，以及材料任务上的承办机构/经办人选择，尚未形成赛事级完整资料和承办关系；该总部直接创建路径是否与承办申请并行保留仍待确认。
- 总部接收并确认承办方发起的赛事信息变更申请；当前没有申请、确认、退回或历史能力。
- 报名后涉及相关俱乐部的赛事变更需要通知，但通知不由CAAU发送；当前也没有向外部报名系统输出已确认变更的接口或交付记录。
- 正式微信身份和依赖真实AppID的验收仍是已确认待办，但按用户当前指令暂缓。

### 2.4 仍待业务确认

- 经营总览、财务、完整运营、通用协同、增长、赞助、裁判、完整资料中心、智能助手和“数据管理”的正式子功能、权威数据源、角色与验收范围。
- 赛事状态生命周期、基础字段、赛事级承办关系、变更审批规则及其对材料、报名和历史的影响；问题见[赛事管理现状与缺口](event-management-gap-analysis.md)。
- 俱乐部/球队资料审核由总部还是承办方负责，以及是否存在多级审核。

## 3. 承办方

### 3.1 已实现并实际验证

| 功能 | 当前能力 | 实际证据与边界 |
| --- | --- | --- |
| 授权赛事和待办可见性 | 只能查询当前机构、当前经办关系和授权赛事内可见任务；跨机构深链、列表、文件和写操作被拒绝 | 真实PostgreSQL/API、Chromium权限反例通过 |
| 旧整包材料办理 | Web本地联调页及Taro源码支持读取要求/模板、草稿、私有附件、提交、退回重交和历史 | 后端与Web真实闭环通过；旧Taro平台完整文件流程未验 |
| 新版自由新增和单份办理 | Web可自由新增、保存、上传绑定、单份提交、处理退回、查看五态/人员/时间/不可变历史 | Web真实多会话和文件闭环通过 |
| 新版小程序本地主流程 | 当前按身份选择→板块式主页进入；唯一“材料审批”板块含材料提交和只读审核进度，继续复用自由新增、V1提交、退回、V2重交、通过及历史 | CAAU-020官方游客模拟器已实测身份优先、主页、两个子模块、A身份任务列表和进度入口；完整V1/V2主流程证据来自早期CAAU-012，当前导航下尚未重跑，不是正式微信登录或真机结果 |
| 自动同步与保护 | Web约2秒短轮询、断线恢复、会话/撤权清理、输入保留和并发冲突处理 | Web多会话延迟和异常场景通过；Taro协调器自动测试通过，开发者工具只验证切出返回立即核对，未逐项复验全部异常 |

### 3.2 已有源码但尚未平台验证

- Taro私有附件选择、ArrayBuffer读取/上传、确认绑定、受控下载、图片预览和文档打开已有源码；自动测试覆盖文件限制、安全文件名、字节传输及bearer不进入URL。
- 开发者工具中 `chooseMessageFile` 能唤起真实选择器，但选择合成txt返回后Promise五分钟无成功/失败，API无上传、草稿无绑定；因此读取、上传、确认、绑定、下载和预览均未平台通过。
- Taro断网保留输入/禁写、恢复核权、401/403清理、撤权、迟到响应隔离和并发输入保护已有源码与协调器测试，尚未在正式AppID开发者工具和真机逐项验证。
- 正式 `wx.login`、服务端code交换、微信账号绑定、会话签发/撤销尚未实现，不能把本地token入口归入本状态的“已有正式登录源码”。

### 3.3 已确认但未实现

- 承办方按首版固定字段填写赛事名称、开始日期、结束日期、赛事地点并提交新赛事承办申请；提交四项必填且结束日期不得早于开始日期。必交营业执照、简介（办赛经验）、现场照片，选交其他文档，文件限制当前只列实现建议。同一机构有申请办理权限的有效经办人共享查看、编辑、提交及补充版本，不限创建人；保留实际操作人/历史，以并发控制防覆盖，跨机构拒绝且提交版本不可修改。当前小程序没有该申请流程。
- 承办方对赛事信息发起变更申请，并由总部确认；当前承办方只能查看任务所带的有限赛事名称/说明，没有变更申请入口。
- 承办方查看与自己所办赛事有关的俱乐部/球队报名资料；正式工程尚无外部报名数据接入、俱乐部对象或该范围页面。
- 后续展示人数、球队、组别、教练联系方式、人工缴费三状态和球队资料审核情况；字段来源、隐私范围和审核流程未实现。
- 正式微信登录、HTTPS合法域名、开发者工具正式项目及真机完整流程保留待办，当前暂缓。

### 3.4 仍待业务确认

- 申请办理及独立申请审核权限由谁授予/撤销与人员停用管理、批准时无有效经办人的处理及获批后新增经办人/撤权/停用的查看权联动、后续材料任务具体配置，以及四项申请资料的正式格式、大小、数量和特殊情况口径（当前只有实现建议）；获批自动最小查看权、不复用宽泛角色、关系与人员授权分记、不自动建任务并沿用现有任务权限，以及此前确认规则不属于待确认规则。
- 同一赛事可有几个承办组织、承办组织内哪些人能申请或申请变更、是否需要机构负责人确认。
- 承办方在外部报名数据上能查看和处理哪些字段，能否导出，以及联系方式的最小显示范围。
- 球队资料审核的状态、退回、版本、责任人和时限；人工缴费标记由谁维护、依据何种凭证及是否需要复核。
- 赛事信息变更对已发布材料任务、截止时间和已提交版本的影响。

## 4. 俱乐部

### 4.1 已实现并实际验证

正式CAAU工程中目前**没有**可归为俱乐部的已实现并实际验证业务功能。没有俱乐部角色、组织绑定、球队模型、报名页面或俱乐部API。原型中的iframe/本地球队台账不是正式工程成果。

### 4.2 已有源码但尚未平台验证

正式CAAU工程中目前**没有**俱乐部业务源码可进入本类。原型外部入口和localStorage数据不纳入正式源码状态。

### 4.3 已确认但未实现

- 俱乐部/球队可报名任意承办方的赛事，不永久归属于某一承办方。
- 俱乐部之间数据隔离；承办方只能看该俱乐部与自己所办赛事有关的资料。
- CAAU后续需要消费报名相关展示信息，并在赛事变更时形成可供外部责任方通知相关俱乐部的事实；当前没有接口或页面。

### 4.4 仍待业务确认

- 俱乐部在CAAU是否需要账号和页面，还是完全由外部报名小程序承载身份与操作。
- 俱乐部、球队、教练和联系人各自由哪个系统作为权威来源，外部ID如何稳定映射。
- 一家俱乐部多队、多赛事、跨地区报名、名单变更和退出赛事的规则。
- 俱乐部能否在CAAU查看赛事变更确认结果、材料或缴费状态；若能，采用何种身份和最小数据范围。
- 未成年人、联系方式和名单数据的采集依据、保存期限、导出/删除及审计规则。

## 5. 由外部报名小程序负责

### 已确认的边界

- 俱乐部/球队的**报名入口与报名提交**由另一个小程序负责，CAAU不重复开发报名入口。
- 俱乐部可跨承办方报名；不能按承办方永久归属切分俱乐部。
- 报名后赛事信息发生变更时，需要通知相关俱乐部，但通知本身不由CAAU发送。

### 尚未确认，不能推定给外部系统

- 俱乐部注册、球队长期档案、名单、资格校验、报名审核、撤回/换人是否全部由外部小程序负责。
- 缴费收款、退款、对账和人工状态录入由哪个系统负责；当前只确认未来可能展示三种人工状态，不代表支付事实来源已定。
- 外部系统向CAAU提供何种API、事件或文件，谁负责重试、对账、重复数据、删除和历史版本。
- 赛事变更确认后由谁调用谁、通知哪些俱乐部、如何确认送达。

在接口和数据责任确认前，CAAU不得复制一套报名写入流程，也不得以原型球队localStorage或演示字段作为外部报名事实。

## 6. 明确保留的平台待办

以下均未因本次产品梳理而取消，也不阻塞当前纯文档任务：

1. 注册并配置有权微信小程序AppID、项目成员和体验成员；当前按用户指令暂缓。
2. 实现并验收正式 `wx.login` 到服务端身份映射；本地opaque token不替代。
3. 准备手机可达的隔离HTTPS API和微信 `request` 合法域名，不提交证书私钥或AppSecret。
4. 在正式项目的微信开发者工具复验附件、异常恢复和完整流程。
5. 在获授权iOS/Android真机分别验收登录、请求、上传/下载、退回重交和权限清理。
