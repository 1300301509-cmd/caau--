## CAAU-005 当前指令与已确认执行规则

用户已授权先提出全段技术设计，再交付第一段真实赛事/任务创建、机构/经办/审核指派、材料要求配置和发布、指定经办方查询，以及必要总部 Web 页面；上传/提交/审核完整实现留第二段。验收使用真实业务 API，不以权限探测代替。技术设计见 [ADR-0004](../adr/0004-material-workflow.md)。

第二段规则已由用户本轮确认（取代第一段未决项）：
- R-014：截止后可保存草稿，禁止正式提交；由总部赛事管理员延期后才能提交。后端用服务器时间校验，延期必须记录操作者、时间、原因及新旧截止时间。
- R-015：同机构换经办人，新经办人接管现有草稿与材料，保留原编辑记录；旧经办人立即失去任务办理权限；重指派与授权变更同事务。
- R-016：首版禁止跨机构直接转移；需要时关闭原任务，再为新机构建新任务。不得自动复制原材料/历史或授予新机构访问权。
- R-017：V1/V2 等提交及审核记录不可修改；保留原提交人、审核人和时间，不因交接改写。

第二段实现真实后端 API：私有文件上传/确认/绑定/下载、草稿并发控制、幂等不可变提交、整包审核与材料级退回原因、重交、延期/同机构交接。验收必须使用真实业务接口；后续页面和微信验收另记。

第三段用户明确授权总部 Web 与承办方 Taro 界面，交互与路径见 [页面设计](material-workflow-ui.md)，实际验收见 roadmap。R-018：配置和发布不得超出当前实际上传格式/大小能力，技术上限不等于正式业务默认。R-019：模板属于总部发布任务的材料要求，不是承办方提交材料。总部仅在发布前可为每项材料上传或移除可选模板；发布时模板与 RequirementVersion 一同冻结，发布后不得悄然替换/删除。当前被指派机构的 active ORGANIZER 才能经后端鉴权下载；其他机构、SYSTEM_ADMIN、审核员、无权/撤权用户拒绝。模板与承办材料共用私有对象存储、安全原文件名显示与格式/大小/哈希校验，但关系和下载权限独立。真实模板库、跨版本改版、微信正式登录/开发者工具/真机仍需单独验收；本地身份入口必须明确标记。
