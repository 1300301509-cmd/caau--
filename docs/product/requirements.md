## CAAU-064 已确认需求 → 整套候选赛程预览（2026-09-24 用户指令）

用户要求复用已确认且未失效的独立需求 revision 与现有排程算法，显式核对赛制、当前全部有效参赛记录、日期/每天时段/场地/时长/缓冲/最短休息及来源；缺失/冲突先澄清、不填业务默认值。第一版单循环，不静默降级。纯计算与独立确定性校验全量合法对阵及硬条件，软偏好逐项说明；单循环本有两队相遇，不以此冒充额外优化。保护已开始/已完成及有保护规则场次，并明确固定范围。区分找到合规、已证明冲突及限额内未找到；独立候选快照绑定需求/基础版本/参赛记录并逐次复核权限及失效。只预览新旧整周场地/时间和受影响比赛，不覆盖/保存/发布正式赛程，不产生正式版本或执行回执。模拟/隔离数据库和浏览器、真实千问、Studio、微信及远程分别验证。当前实现范围和未确认的现场状态规则见[候选规格](agent-schedule-candidates.md)和[ADR 0026](../adr/0026-agent-whole-schedule-candidate-preview.md)。

## CAAU-063 统一助手排程需求收集（2026-09-24 用户指令）

用户要求收集整周日期、赛事参赛球队可用/不可用时间、明确对阵偏好及必须/尽量条件；澄清、逐轮替换/取消、逐条件来源/确认状态、摘要和可确定冲突随会话保存，并按当前权限恢复。需求确认与单场改期的实际 DRAFT 确认**完全分开**：不生成/保存赛程、不产生执行票据，修订后旧确认失效。模型只提出候选，服务端核对日期、EventTeam 参赛和当前赛事操作权限；更多未知赛制与排程硬规则不得自行补全。角色、异常路径与技术限额见 [CAAU-063 排程需求规格](agent-schedule-planning.md)，实现取舍见 [ADR 0025](../adr/0025-agent-planning-requirement-revisions.md)。

## CAAU-005 当前指令与已确认执行规则

用户已授权先提出全段技术设计，再交付第一段真实赛事/任务创建、机构/经办/审核指派、材料要求配置和发布、指定经办方查询，以及必要总部 Web 页面；上传/提交/审核完整实现留第二段。验收使用真实业务 API，不以权限探测代替。技术设计见 [ADR-0004](../adr/0004-material-workflow.md)。

第二段规则已由用户本轮确认（取代第一段未决项）：

统一助手可在无任务时查询本人有权赛事的真实赛程列表和单场详情：明确赛事、日期范围／“这周”／“周三”等北京时间相对日期与球队；“刚才那场”只有唯一已授权单场来源时才可引用，不猜不确定的场次。同名赛事、同名球队、多场匹配或缺失赛事时先要求选择／澄清。回答须基于当次赛程，注明赛事、北京日期、草稿／已发布状态、版本、对阵、时间与场地；零结果／尚无赛程不是“球队有空”。查询本身不改任务、票据或赛程版本，明确发起单场调整才进入已有预览、人工确认单场 DRAFT 的工作流，未开放批量写入、发布及新业务工具。历史查询结果须持久注明赛事及实际来源比赛，并在恢复、发送模型及返回前对所有历史来源重新鉴权（包括未创建业务任务的会话）；跨赛事撤权后历史不得泄露。服务端与独立 Studio 共用受控业务逻辑；Web 与小程序消费生成客户端。具体技术决策见 [ADR 0024](../adr/0024-agent-readonly-schedule-tools.md)。

## CAAU-050 补充：赛事工作人员

用户确认在比赛管理中心增加“人员管理”，用于裁判等工作人员登记，并为赛程编排保留单场人员接口。总部和承办方均可维护，承办方仅限自己的赛事。首版按赛事建立名单，支持岗位、姓名、联系方式、单位、职责和备注；名单变化与历史场次快照分离，不创建人员账号。实现范围及接口见[人员管理](../runbooks/event-staff.md)。

CAAU-051：用户确认小程序先做人员管理与单场人员安排；复用上述赛事权限与人员库，为已发布单场比赛选择工作人员，维护本场岗位与备注。暂不扩展草稿赛程指派、全局人员账号或自动排班。

导航更正：小程序首页主模块为【我的比赛】，【人员管理】属于其下的子模块，不独立占据首页主模块位置。

CAAU-052：用户要求将其它模块接入承办方小程序。按现有比赛中心模块接入球队管理、赛程编排、物料管理和赛事情况，均放在“我的比赛”下并复用原权限；不恢复已暂缓的球队端，不新增总部审批权限。入口及边界见[小程序比赛模块](../runbooks/miniapp-competition.md)。

CAAU-057：用户要求增加专用于超级管理员开发测试的 Web 功能。本地模式默认进入总部超级管理员，并在 Web 左下角自由切换固定测试账号权限；切换只更换当前标签页的后端测试会话，不修改正式账号角色。正常模式继续按正式登录账号判断权限，不显示测试切换器，也不得开放本地签发接口。

CAAU-058：用户进一步明确身份切换要用于测试服务器，而非仅限开发者本机。测试服务器必须先用正式总部超级管理员账号登录，随后才可在 Web 左下角切换固定测试身份；签发记录真实操作管理员。普通账号、未登录请求和 Bearer 会话不得调用测试签发接口。生产阶段必须强制关闭该能力。

## CAAU 平台治理与监控中心

用户已确认总部超级管理员治理入口、账号与会话、全模块审计、模型逐调用用量及可选额度、成本核对、完整现存对话审查、自建监控与飞书告警。详细范围与指标见 [平台治理规格](platform-governance.md)，任务及验收见 [实施计划](../planning/caau-governance.md)。不扩展到充值套餐、用户扣费、任意改库或未实现业务的演示统计。

## CAAU-084 智能助手三级记忆

用户要求补齐三级记忆。L1 让同一会话的长对话经摘要和最近消息继续理解上下文，原始消息仍可恢复；L2 继续以已有任务、排程需求单和 checkpoint 保存明确条件与步骤；L3 只将本人明确确认的个人偏好跨会话用于回答和方案讨论，并提供查看、删除。新对话不继承旧任务；摘要和个人偏好都不能替代当前授权业务数据、正式赛事规则、排程约束、权限或人工确认。仅在对话说“记住”不等于保存，需点击明确保存动作。知识资料检索另行设计。

## CAAU-087 赛程编排自然语言需求与分时段上限（2026-09-27 用户反馈）

用户要求排程助手在已有需求单中理解自然语言补充，例如“每两只队伍各交手一次，上午最多排一场，下午可以排两场，晚上可以排一场”，不依赖代码关键词命中才接受单循环。赛事日期和参赛球队从当前有权任务与业务资料继承，不要求重复输入。上午、下午、晚上每日场数作为候选排程的硬条件；时段钟点和“整个赛事／每个场地”的统计范围未明确时，保存待补条件并询问，不能忽略后生成候选。需求确认、候选生成与正式赛程写入仍是不同动作；本任务不开放整套赛程保存或发布。具体行为见[需求收集规格](agent-schedule-planning.md)和[候选规格](agent-schedule-candidates.md)。
