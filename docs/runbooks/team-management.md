# 球队管理操作与验证（CAAU-041）

## 赛事竞赛组别（CAAU-099）

赛事管理员先在【本赛事球队 → 新建组别】创建竞赛组别，例如“U12 男子组”；组别只属于当前赛事，有稳定 ID、启用状态和版本。新建球队并加入赛事、或从已有档案加入赛事时，必须明确选择当前赛事中启用的组别。球队主档案没有组别字段；同一俱乐部可建立不同球队档案，分别加入不同组别。一个球队档案在同一赛事仍只对应一条参赛记录。

Web 和承办方小程序的球队列表均显示赛事组别。旧参赛记录显示“待归组”，由有权人员在【编辑本赛事球队】中明确指定；系统不会按队名或历史比赛猜组别。已进入当前赛程的球队不能从一个已确定的组别直接改至另一组别，应先处理赛程；旧记录从待归组首次归组可继续，但旧赛程须重新核验。组别仍有参赛中的球队时不能停用。组别编辑、归组均检查赛事权限和 revision；发生 409 时刷新核对再修改。完整排程和发布的组别校验见[赛事竞赛组别规格](../product/event-divisions.md)。

## 移出本赛事（CAAU-047）

本赛事球队默认只显示“参赛中”。在球队行点击“移出本赛事”，核对球队、赛事及赛程影响后确认；取消不会写入。成功后从参赛中列表消失，切换“参赛状态 → 已退出”可查看原资料。球队主档案、其他赛事资料、已发布赛程和历史均保留。若球队已用于赛程，原赛程会提示球队不可用，须重新编排或处理后才能再次发布。

操作复用现有更新接口，携带当前资料及 revision，设置 active=false；后端仍检查赛事权限、CAS 并记录版本与审计。冲突、失权或网络结果不明时不显示成功，请取消并刷新核对。已退出球队可沿用既有“编辑资料 → 继续参加本赛事”开关恢复；“从档案添加”不会重建或覆盖已有赛事记录。

## 当前使用状态

CAAU-046 独立球队端已由用户主动暂缓且未完成。当前由授权总部 Web、承办方小程序维护球队；统一助手的受控建队仅在明确预览和确认后写入，不启用球队自助账号、认领、公开赛事目录或球队端报名窗口改造。

手工录入、编辑、从档案加入赛事及赛事资料独立编辑均由受保护 API 提供；`Team` 与 `EventTeam` 分表、分版本保存，重复加入同一赛事不会刷新快照，主档案与赛事资料双向都不自动同步。

## 本地入口与身份

- 登录：`http://127.0.0.1:5175/login`
- 球队管理：`http://127.0.0.1:5175/competition?module=teams`
- API 健康检查：`http://127.0.0.1:3000/api/v1/health`

本地最直接的操作身份是已有正式账号 `caau.admin`；本机开发库只读核对为 active、无需首次改密且具有 `HEADQUARTERS_SUPER_ADMIN`。密码只从权限为0600的忽略文件 `.local/auth/caau-029-dev-login.txt` 取得，不在聊天、日志或文档中复制。也可使用具备目标赛事有效 `EventGrant` 的 `EVENT_MANAGER`，或同时具备目标赛事有效承办关系和本机构有效申请办理授权的 `ORGANIZER`。`REVIEWER`、普通 `SYSTEM_ADMIN`、只有赛事基本查看权或只有材料任务授权的账号不能据此维护赛事球队。

登录后进入【比赛管理中心 → 球队管理】：

1. 【球队档案】可在无账号、无赛事时录入球队。必填球队名称、负责人、联系方式、省份和城市。
2. 选择当前赛事，先建立竞赛组别，再在【本赛事球队】点击【从档案添加】并选择组别；也可直接【录入球队】，选择组别后原子创建档案并复制资料加入当前赛事。
3. 两个页签分别编辑，保存不会同步到另一侧。修改档案后再次添加已关联球队，也不会覆盖原比赛资料。
4. 档案可停用归档，赛事球队可标记退出，均保留原记录及版本。
5. 编辑【球队档案】只更新主档案；编辑【本赛事球队】只更新所选赛事快照。页面顶部提示和后端数据模型都不会执行自动同步覆盖。
6. 409 表示版本变化或重试请求不一致；表单保留输入，请关闭窗口、刷新核对后重新修改。不能通过连续点击强行覆盖他人修改。

总部超级管理员可管理全范围。普通经理需有效赛事授权；承办人员需有效赛事承办关系及办理授权。无权限时返回错误说明，不以空表代表加载成功。详见 [权限及产品范围](../product/team-management.md)。

## 当前操作缺口与限制

- 没有球队自助账号、绑定写入口、邀请、认领或球队端小程序；这些属于已暂缓范围，不在当前 Web 中补做。
- 没有公开赛事目录或球队端报名窗口；现有赛事球队关系不是报名记录。
- 只能选择当前账号可见且可操作的赛事；普通赛事查看权、审核权或材料任务权限不自动授予球队写权限。
- 【从档案添加】只列出当前可见、未归档且尚未加入本赛事的档案；重复添加返回既有赛事记录且不会重新复制主档案。
- 当前档案搜索和分页在浏览器端处理授权接口返回的完整列表，数据量扩大后的服务端分页仍是已知技术限制。
- 不提供物理删除或自动同步。这是历史与快照保护边界，不是当前应补齐的操作按钮。

## 接口

- `GET /api/v1/teams/organizations`：有权录入的机构。
- `GET /api/v1/teams`、`POST /api/v1/teams`：授权档案列表、新建。
- `PUT /api/v1/teams/:id`：档案修改及归档，携带 expectedRevision。
- `GET /api/v1/events/:eventId/teams`、`POST /api/v1/events/:eventId/teams`：赛事独立列表与添加。
- `PUT /api/v1/events/:eventId/teams/:id`：赛事专属资料及退出，携带 expectedRevision。
- `GET /api/v1/events/:eventId/divisions`、`POST /api/v1/events/:eventId/divisions`：本赛事组别列表与新建。
- `PUT /api/v1/events/:eventId/divisions/:id`：组别改名、启停，携带 expectedRevision。

契约由 Nest DTO 生成。创建 ID 作为幂等键；创建球队时可携带 eventId，此时必须同时携带 divisionId；从档案加入赛事也必须携带 divisionId。前端只消费 @caau/api-client。不得通过数据库脚本给真实用户强制认领球队。

## 本地验证

固定工具链下先 `pnpm build`，再 `pnpm db:test`。后者只在独立 test 容器创建和清理自身临时数据库；包含 `scripts/teams.integration.mjs` 及使用实际 API 的 `scripts/teams-browser.integration.mjs`。CAAU-047 全套 66/66 通过：浏览器覆盖移出取消、已发布赛程影响提示、确认移出、默认列表移除、已退出筛选、主档案保留和窄屏布局；后端覆盖权限、CAS、操作人/时间/审计、其他赛事隔离、已发布赛程不改写及退出球队拒绝新编排。需要3000/4173空闲，不能复用已有业务服务。

按 [数据库运行手册](database-contract.md) 使用 `pnpm db:migrate:deploy` 追加迁移，禁止 reset。迁移后 `pnpm db:api` 恢复 API；Vite5175继续消费新接口。未新增任何本机演示球队。邀请认领、小程序页面、正式微信登录与真机结果另验，不将本地数据库或浏览器测试计为微信验收。
