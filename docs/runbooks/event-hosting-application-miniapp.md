# 承办方小程序赛事承办申请

状态：CAAU-027 D 源码、正式 weapp 构建、真实 API/PostgreSQL 回归及官方开发者工具页面核验已完成；开发者工具文件选择闭环仍受平台自动化桥阻塞，真机未运行。

## 1. 入口与边界

小程序继续使用现有板块式主页，不配置 tabBar。选择本地承办方身份后：

1. 主页“业务板块”选择“承办申请”；
2. 下方点击“申请办理”；
3. 进入 `/pages/hosting/index`。

该入口不依赖主页已选赛事。当前身份只要具有某机构的有效承办申请办理权限，即使没有任何赛事、赛事授权或材料任务，也可为该机构建立申请。申请机构列表由后端身份响应逐次权威返回，客户端不从赛事或历史申请猜测机构。

原“材料审批→材料提交/审核进度”入口、赛事选择窗和任务规则保持不变。承办申请获批不会自动创建材料任务，也不会把赛事基本信息查看权当成任务办理权。

本阶段复用本地测试身份，不实现正式微信登录、通知、生产发布或总部审核操作。

## 2. 页面能力

- 本机构申请列表及草稿、待审核、审核中、待补充、已通过、已驳回六态筛选；同机构有权经办人看到同一列表，不按创建人过滤。
- 新建申请后机构不可更改；草稿表单包含赛事名称、起止日期、省市区、详细地址、场馆名称和办赛经验简介。
- 原生日期和地区选择器；草稿允许不完整，正式提交前客户端提示，后端仍执行最终全量校验。
- 私有附件分为营业执照、现场照片和其他文档：营业执照恰好1个，现场照片1～10个，其他文档最多5个；PDF/JPG/JPEG/PNG及单文件10MiB限制与后端一致。现场照片不接受PDF。
- 上传执行意图→二进制内容→服务端确认/绑定；下载每次重新鉴权，图片使用预览，PDF交系统文档查看器。历史版本附件不可因当前草稿移除而消失。
- 正式提交使用安全随机幂等键并二次确认；未知结果不自动重复执行，保留同一命令供显式核实/重试。
- 待补充在同一applicationId修改并生成Vn+1；显示补充意见、不可变版本、相邻字段/附件差异和实际操作ID/服务器时间历史。
- 已驳回只读，页面明确提示另建新申请；已通过显示唯一正式赛事入口、来源版本和承办机构。
- `/pages/event-info/index`只通过后端基本信息查看权读取获批赛事，不显示赛事编辑、审核或材料任务入口。

## 3. 同步、冲突与失权

页面在前台完成一批读取后约3秒再次核对，切后台停止，返回前台立即核权；正常情况不显示轮询、连接或最近同步技术状态。

- 表单缓冲和服务器草稿分离；轮询不会覆盖未保存输入。
- 草稿revision变化时显示冲突并保留输入。经办人必须显式选择“采用服务器草稿”或“核对后保留我的输入”，后者基于最新revision再次保存。
- 切换申请、身份或离开存在未保存输入/未知提交时使用确认或平台离页提醒。
- 断网保留输入并停写，恢复后自动核对；迟到响应通过会话token、页面代次和前后台状态丢弃。
- 401清空全局会话与受保护内容；403清空申请列表、详情、附件引用、表单及待重试命令，但不扩大其他模块权限。
- 同一提交按钮在处理中禁用；后端CAS、幂等键和不可变版本仍是最终并发边界。

## 4. 本地准备与启动

使用官方Node.js 24.20.0、pnpm 10.32.1及Taro 4.2.1：

```sh
CAAU_IDENTITY_MODE=local corepack pnpm db:api
corepack pnpm hosting:demo
TARO_APP_API_BASE_URL=http://127.0.0.1:3000 corepack pnpm --filter @caau/miniapp build
```

开发者工具导入 `apps/miniapp`；跟踪配置仍为 `touristappid`、`urlCheck=true`，电脑模拟器连接回环API。不要关闭域名校验或把本地opaque会话描述成微信登录。

固定身份：

- **承办方 A 经办人**：查看A机构五态合成申请，包含待补充V1与补充后V2获批。
- **承办方 B 经办人**：查看B机构范围，用于跨机构隔离及驳回只读体验。
- 总部操作继续在 <http://127.0.0.1:5173/hosting-applications> 使用“总部审核员甲/乙”。

## 5. 从主页开始的完整体验

### 5.1 新申请 V1→补充→V2→通过

1. 小程序选择“承办方 A 经办人”，进入主页。
2. 选择“承办申请”→“申请办理”→“建立新申请草稿”。申请机构保持只读。
3. 填写名称、日期、地区、地址、场馆和办赛经验；先保存草稿。
4. 上传1个营业执照和至少1张现场照片，其他文档可不上传。点击“正式提交申请”并确认，看到待审核V1。
5. Web以“总部审核员甲”打开同一申请，执行“开始审核”→“要求补充”，填写明确意见。
6. 小程序返回前台，看到待补充、意见及V1；修改任一已允许字段或附件，保存后点击“提交补充版本”，生成V2。
7. Web可由甲或乙接续开始审核并通过。
8. 小程序返回前台，看到已通过、V1→V2字段/附件差异、全部历史及唯一“查看正式赛事基本信息”入口。
9. 进入正式赛事页，只能查看基本信息；材料审批仍只显示总部另行建立并明确指派的任务。

### 5.2 驳回、协作与异常

- 新建另一申请并由Web驳回；小程序原申请只读且没有保存/重交控件，上方仍可独立建立新申请。
- 两个小程序会话使用同机构经办人从同一revision编辑；一方保存后另一方保存得到冲突，输入保留，显式核对后才能继续。
- 用B身份访问A申请深链或附件应由API拒绝；切到B后A列表和表单立即清除。
- 撤销办理权限、会话过期或停用人员后返回前台，申请内容清除；普通网络中断不清除输入。
- 响应未知时只能点击“沿用原命令核实/重试”，不得重新生成命令造成重复提交。
