# CAAU-012 C：Web 演示与验收

状态：基于完整 `e73e577`，Web 本地验收完成；Taro 新版页面、微信工具/真机不在本次通过范围。交互依据见 [Web 设计](../product/individual-material-web.md)，后端操作见 [单份材料手册](individual-materials.md)。

## 1. 可操作的本地演示

使用官方 Node24.20.0 / pnpm10.32.1；先按 [数据库文档](database-contract.md) 准备 dev 数据库并确认六份迁移已应用。不得 reset、删除卷或修改旧迁移。

```sh
corepack pnpm install --frozen-lockfile
# 终端一：必须显式开启本地身份；默认模式关闭，业务接口会返回503。
CAAU_IDENTITY_MODE=local corepack pnpm db:api
# 终端二：
corepack pnpm dev:admin
# 终端三：只新增合成身份、机构、赛事及一份已发布的空参考任务。
corepack pnpm materials:demo
```

打开 **http://127.0.0.1:5173/materials**。页面明确显示“本地测试身份”，可选择五个固定身份后进入；后端签发并验证约 8 小时有效的 opaque 会话，不再导入 JSON。固定身份准备不创建赛事、授权、任务或材料，也不修改已有记录。若另行运行 `materials:demo`，该命令仍只追加明确标识的合成赛事与任务；本轮身份准备不需要它。

可在同一浏览器的不同标签页分别选择承办方与审核员。token 只在当前标签页 `sessionStorage`，不会通过 localStorage 或应用广播覆盖其他标签页；刷新后重新调用后端验证并恢复。会话过期/注销后受保护内容和存储 token 会清除，页面明确提示重新选择并进入。后台页面暂停同步，返回前台会重新核对。不要从开发者工具复制 token，也不要放入 URL、日志、聊天或 Git。完整本地身份边界见[身份操作文档](authorization.md)与[ADR-0009](../adr/0009-local-test-identity-switching.md)。

演示顺序：
1. 承办选择“单份演示任务”，自由新增两份材料。任选一份填写说明或上传附件；上传确认后**保存草稿**绑定文件，再“单份提交”并确认。另一份仍可保持待提交。
2. 甲、乙共享队列自动出现待审核材料。查看不改变状态；甲点击“开始审核”并确认。
3. 乙在自己的详情看到审核中，填写原因/修改要求，“退回修改”并确认。承办无需刷新，详情自动变为退回修改。
4. 承办修改、保存、重交 V2。甲开始审核，乙接续通过。核对操作人、稳定 ID、服务器时间、V1/V2正文与附件；通过后不可编辑。
5. 旧整包入口选择原任务，仅展示原整包提交/审核及私有下载，不伪装成旧时已逐份审核。原授权仍生效；新共享审核员不因此获得旧整包权限。

本机交付时已实际运行演示命令，并用三个独立 Chromium context 导入 dev 身份、自由新增并提交一份“场地保障材料（合成演示）”；两名审核员队列均已自动出现。它保留为待审核，便于接续第2步。自动化验收使用另一套临时 test 数据库，不会把 test fixture 混入 dev。

## 2. 同步与冲突操作

- 队列每页5份，操作历史每页10条；自动更新保留当前页码、筛选和本地输入，不承诺同一行在实时排序中的固定位置。
- 同步批次不重叠，结束后约2秒再次获取权威快照；目录/身份同批并行读取，历史按版本补读。已鉴权快照先更新状态，不被目录或历史读取阻塞。正常同步不显示连接状态、最近核对时间或轮询间隔，也不保留状态栏空位。短暂失败静默重试；连续6秒仍无法更新时只显示一个可立即重试的提示。网络失败继续退避至30秒，断线/后台禁写；会话过期和权限失效使用单一可操作提示。
- 草稿有外部更新时保留输入，显示冲突；先“核对后保留输入”或确认“采用服务器草稿”，再显式保存。翻页不会隐式丢弃输入；换材料/身份/旧历史需确认。
- 审核弹窗固定当时的 revision/submissionId。并发一方收到409后显示冲突，不覆盖另一方结果，原意见保留。未知提交结果不冒认成功；恢复后只能“沿用原命令重试”，不自动重放写操作。
- 401 清空受保护内容并停止；403/草稿权限降级清空目标、输入、历史、意见与未确认命令，再重查有权范围。会话/选择/生命周期 epoch 丢弃迟到结果；没有浏览器持久化草稿或文件缓存。已实际下载到磁盘的文件无法追回。

`corepack pnpm db:test` 使用真实隔离 PostgreSQL、真实 Nest HTTP、生产 Web 构建及独立 Chromium contexts；占用3000/4173且不复用已有服务。**先停止演示 API再运行**。不调用 dev reset，不删数据卷。

| 构建与普通测试 | 三应用构建通过；40项包/应用/HTTP测试通过，其中客户端20项，新增6项协调器测试 |

最终同步样本 **15条**：p50 **1821ms**，p95 **2093ms**，max **2093ms**。恢复连接后重新核对 **108ms**（单次局域测试条件，不是恢复时限承诺）。Chromium `145.0.7632.6`。口径为写HTTP响应完成至另一独立浏览器目标DOM，帧级检查（约17ms及CDP调度误差），同机单调时钟；分位数使用 nearest-rank。不是精确数据库 commit 时间、推送延迟或生产 SLA。原始脱敏样本见 [JSON](../evidence/caau-012-web/multi-session-results.json)。

调试中曾出现选择框可访问名称不精确、375px布局溢出、串行目录/历史阻塞及粗粒度断言观测使本地5秒门槛失败（5462ms）。修正后仍保留5秒门槛，最终完整重跑通过；上一次修正后完整运行亦42项通过，p95/max2028ms。日志保留在忽略的 `.local/evidence/caau-012-web/`，不隐藏失败或以降低门槛过关。首次 dev 演示未开启 local 身份而503，按文档开启后通过；未因此改默认关闭的安全配置。
