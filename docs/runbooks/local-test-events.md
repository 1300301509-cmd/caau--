# 本地测试赛事与授权

本操作复用 [固定本地测试身份](authorization.md) 和现有赛事/授权 API，仅准备两项本地测试赛事及赛事范围；不创建资料任务、附件、材料或提交，不修改 schema、迁移或业务规则。

## 现有能力边界

- `POST /api/v1/events` 可由总部赛事管理员创建只有名称/说明的赛事，并自动授予创建者 EVENT_MANAGER 赛事范围。
- `POST /api/v1/authorization/event-grants` 可由系统管理员把已有 ORGANIZER/REVIEWER 成员授权到赛事。本地准备脚本仅用系统管理员会话调用此现有接口，不直接写 Event/EventGrant。
- 当前**没有赛事级承办方字段或关系**。“测试大区赛 A 由承办方 A 承办”在本轮只能落实为“承办方 A 经办人具有赛事 A 的 ORGANIZER grant”；真正的任务经办指定必须创建 `MaterialTask + TaskScope`，本轮明确不创建，因此不能将 grant 描述成已确认的赛事级主承办关系。
- 审核员甲/乙的两个赛事 REVIEWER grant 是后续共享审核的授权前提；实际开始/接续审核还必须存在资料任务及已提交材料。本轮没有可执行审核对象。
- `GET /api/v1/events` 对总部赛事管理员按 EVENT_MANAGER grant 返回无任务赛事；对审核员/经办人则通过可见资料任务间接返回。因本轮无任务，审核员/经办人的业务赛事列表和 `/materials` 承办方列表为空是当前查询设计，不是赛事 grant 失败。

## 准备

保持 dev 数据库、local 模式 API 和 Web 运行：

```sh
CAAU_IDENTITY_MODE=local corepack pnpm db:api
corepack pnpm dev:admin
corepack pnpm events:local
```

`events:local` 执行以下步骤：

1. 通过本地测试会话端点签发并验证上一步五个固定身份。
2. 总部赛事管理员调用现有赛事列表/详情/创建接口。脚本用说明中的稳定本地标识识别“测试大区赛 A/B”；存在时只读取验证，不更新，缺失时才创建。
3. 通过现有目录接口取得固定成员 ID；系统管理员调用现有赛事授权接口授予审核员甲、乙两个赛事，以及 A/B 经办人各自赛事。重复授权返回 409 后必须继续用受保护范围接口验证，不能把任意冲突当成功。
4. 分别使用五个真实 bearer 会话调用 `GET /api/v1/authorization/event-scopes/:id`：管理员及两名审核员对 A/B 均为 200；A 经办人仅 A 为 200、B 为 403；B 经办人仅 B 为 200、A 为 403。
5. 额外确认管理员业务赛事列表包含 A/B。CAAU-016 初次准备时另确认两个赛事没有材料任务；后续阶段可以另行明确创建任务，重复运行本命令不会创建、更新或删除任务。全部临时会话随后注销。

命令可重复运行，不重复创建标记赛事或授权，不更新已有赛事。事件 ID 和当前机器可用链接写入忽略文件 `.local/db/local-test-events.json`；文件不含 token。若索引指向的赛事名称/标识不匹配，脚本失败并拒绝覆盖索引或业务数据。

## 查看入口

以“总部赛事管理员”进入 **http://127.0.0.1:5175/materials**，页面“赛事列表”显示两个无任务赛事。每项链接为 `/materials?event=<赛事ID>`，可刷新恢复当前标签页身份；当前机器的完整 A/B 链接也由 `events:local` 输出并记录在忽略索引中。

审核员/经办人没有无任务赛事的页面列表。其授权范围须以上述受保护 `event-scopes/:id` 的 200/403 结果判断；不得以页面看不到赛事推断授权失败。需要在页面办理或审核时，后续任务必须另行明确授权创建。
