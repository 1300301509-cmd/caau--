# 总部赛事管理 Web

## 范围

入口：`http://127.0.0.1:5175/events`。

当前页面复用受保护的 `GET /events` 和 `POST /events`，只展示赛事名称、说明、创建时间和 ID。仅 `EVENT_MANAGER` 可创建赛事；列表仍由后端按当前身份范围过滤。审核员、承办方和系统管理员不能通过隐藏入口获得赛事创建权限。

赛事级承办关系尚未实现。页面不得把 `EventGrant` 或材料任务的机构/经办人指派显示为赛事承办方，设计边界见[赛事级承办关系最小设计](../product/event-organizer-relationship-design.md)。

## 本地体验

先按[身份文档](authorization.md)以 local 模式运行 API，并启动 Web：

```sh
CAAU_IDENTITY_MODE=local corepack pnpm db:api
corepack pnpm dev:admin
```

1. 打开 `/events`。
2. 选择“总部赛事管理员”并进入。
3. 点击“创建赛事”，填写赛事名称和赛事说明。
4. 确认创建后，新赛事出现在“我管理的赛事”，右侧展示详情并更新为 `/events?event=<id>` 深链。

不要用固定 A/B 准备脚本替代用户手工创建；不要为赛事创建材料任务。若改用总部审核员或承办方身份，页面应明确拒绝赛事管理，直接调用 `POST /events` 也必须返回 403。

## 已支持与暂缓

已支持：赛事名称（最多120字）、说明（最多2000字）、创建时间和系统 ID。

暂缓：赛事级承办机构/经办人、地点、日期赛程、级别、状态、报名与变更审批等未建模或未确认字段。不得把演示值写成正式默认值。
